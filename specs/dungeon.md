# ダンジョンのルート進行

この文書は、単一階層の固定ルートと、戦闘・会話ノードの進行を定める。移動は接続先ノードの選択で行い、キャラクターの自由歩行は扱わない。全体の責務境界は[仕様概要](overview.md)、会話と戦闘の処理は[街・会話仕様](adventure.md)と[戦闘仕様](battle.md)を参照する。

## 型付きルート

ルート定義はダンジョンID、入口ノードID、ノードの配列を持つ。ノードは一意なID、表示名、接続先IDの配列を持ち、種別に応じて次を定義する。

| 種別 | 内容 |
| --- | --- |
| `start` | 入口。初期状態で解決済みになり、接続先を選べる |
| `battle` | 既存の戦闘コアへ渡す敵編成と、勝利後の接続先 |
| `conversation` | 既存の会話定義への参照と、完了後の接続先 |
| `boss` | 既存の戦闘コアを使う最後の戦闘。勝利でダンジョンをクリアする |

定義は1つの入口と終端のボスを持つ有向非巡回グラフで、全ノードは入口から到達可能にする。参照先のノード・会話・戦闘者が存在し、IDが重複しないことを開始時に検証する。ランダム生成や複数階層は扱わない。

初期ルートは「入口 → 崩れた通路の戦闘または足跡の調査会話 → 遺跡の守り手のボス戦」とする。2つの分岐は同じボス戦へ合流する。

## 状態

`DungeonState`は次を保持する。

| 項目 | 意味 |
| --- | --- |
| `dungeonId` | 進行中の固定ルート |
| `currentNodeId` | 現在位置。ノードへ入った時点で更新し、処理中も保持する |
| `activeNodeId` | 戦闘または会話を処理中のノード。処理中でなければ`null` |
| `resolvedNodeIds` | 一度処理を終えたノードID。入口は初期状態から含む |
| `outcome` | `ongoing`、`cleared`、`failed`のいずれか |
| `activity` | 処理中なら既存の戦闘状態または会話状態。ルート選択中・終了後は`null` |
| `party` | 次の戦闘へ引き継ぐ味方定義と現在HP |
| `flags` | ダンジョン中の会話で更新されたフラグ |

## ルート操作

- `createDungeonState`は入場PTと街のフラグを受け取り、入口を現在位置かつ解決済みにした状態を作る。味方編成をルート定義に持たない。
- `getAvailableDungeonNodes`は、探索継続中で処理ノードがなく、現在位置が解決済みのときだけ接続先を返す。解決済みノードは候補に含めない。
- `enterNextDungeonNode`は、現在位置から直接接続され、未解決のノードだけを開始する。接続していないノード、ノード処理中の移動、解決済みノードの再実行は状態を変えずに拒否する。
- 戦闘または会話が完了すると、処理中ノードを解決済みにして`activeNodeId`と`activity`をクリアする。現在位置はそのノードに残り、そこから接続された次の候補を選べる。

## 戦闘ノード

ノードに入ると、ダンジョン状態の味方HPとノード定義の敵を使って既存の`createBattleState`を呼び出し、既存の`advanceBattleToNextAllyInput`で味方入力待ちまで進める。攻撃は既存の`performBasicAttackAndAdvanceToAllyInput`を使い、攻撃イベントと直後の敵行動を返す。

味方のHPと戦闘不能状態は各戦闘の終了後にダンジョン状態へ戻し、次戦に引き継ぐ。次の戦闘ではノード定義の敵HPと行動時刻を初期化し、論理時刻を新しい戦闘の値から始める。全味方が戦闘不能になると探索結果を`failed`にし、以後の移動を拒否する。通常戦闘ノードの勝利ではルート選択へ戻る。ボスノードの勝利で`cleared`となり、ダンジョンを終了する。ボス撃破はゲーム全体の終了ではない。

## 会話ノード

会話ノードは`AdventureDefinition`にある会話を既存の`getCurrentConversationScene`、`advanceConversation`、`chooseConversationOption`で処理する。会話中はダンジョン側に会話状態を保持するため、会話操作が探索全体を街へ移動させない。終了時は会話のフラグ更新をダンジョン状態に戻し、会話ノードだけを解決済みにして元の探索位置から接続先を選べる。

## ブラウザ画面

街の[出撃編成](party.md)から選んだPTで探索を始める。`/?dungeon=1`は新規ゲームのロッシ単独で探索を始める確認用入口。ノードはHTMLボタン、接続はSVGで表示し、固定の座標を画面定義に持つ。選択可能なボタンは`getAvailableDungeonNodes`の結果だけから有効化し、押下時には必ず`enterNextDungeonNode`を呼ぶ。戦闘・会話の画面切替中も、同じゲームセッションが`DungeonState`と仲間一覧を保持する。退出時にもHP・PT・会話フラグを維持し、ページ遷移で初期化しない。

表示中はルート図を水平方向にドラッグできる。縦スクロールは行わず、表示ノードの両端がそれぞれ画面中央へ来る位置まで移動できる。接続線はノード画像の通常位置にある左右外側の中心から伸ばし、カードの下を通さない。画像寸法から線の位置を計算するため、ホバーでノードが浮いても線端点は動かない。描画・リサイズ後に位置を測り直し、ドラッグ時は線とカードを同じレイヤーで動かす。背景はルート図より小さい距離だけ動かし、ぼかしと不透明度でノードの読みやすさを保つ。入口と状態文字ラベルは表示しない。ノード題名は種別ごとに固定し、既存の戦闘・会話・ボスは「戦闘」「思わぬ遭遇」「ボス」とする。進行経路から外れた過去分岐は題名を隠す。選択可能なノードには`focus`素材を使い、他のノードには`unfocus`素材を使う。先にある未選択ノードには題名を表示してぼかさず、進行で通らなかった過去分岐だけぼかす。現在地・踏破済み・選択可能・未到達の状態はスクリーンリーダーに伝える。ルート背景、実行用コピー、未使用の元素材は[素材メモ](../art-src/README.md)を参照する。

狭い画面で探索を始めたときは入口を隠し、選択可能な分岐を中央に置く。探索が進んだ後は現在地と選択可能なノードが見える範囲に配置し、リサイズにも追従する。

会話場面では既存の会話表示を使い、Spaceまたは画面クリックで文章を進め、ボタンまたは数字キーで選択肢を選ぶ。会話が終わると同じ探索状態のルートへ戻る。戦闘場面では専用見出しを出さず、現在の`DungeonState.activity`を表示し、攻撃には`performDungeonBasicAttack`を使う。戦闘結果の確認後は通常ノードならそのノードからの選択へ戻り、ボス撃破・味方全滅なら探索結果を表示する。単体戦闘デモの`/?battle=1`は独立した初期状態を使う。

## 受入例

- 入口から戦闘分岐と会話分岐のそれぞれを選び、共通のボスノードへ到達できる。
- 処理中ノードがあるときはルート移動できず、接続外・解決済みノードも選べない。
- 会話完了後も現在位置は会話ノードのままで、次の接続先を選べる。会話で立ったフラグはダンジョン状態に残る。
- 敵を倒して通常戦闘ノードを終えた後、味方HP・戦闘不能は維持され、次の敵HPと行動時刻は初期値になる。
- ボス勝利で`cleared`、味方全滅で`failed`となり、終了後は次ノードへ移動できない。
