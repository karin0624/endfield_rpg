# 戦闘画面と構図設定

戦闘画面、構図設定、描画の責務を定める。現在扱うフィールドは`ground1.glb`と`landscape1.png`の組み合わせ1つである。Babylon.jsは`src/web/`に閉じ、ゲーム状態にメッシュ・テクスチャ・カメラを入れない。戦闘ルールは[戦闘仕様](battle.md)、UIの配色・状態表現は[デザインガイドライン](../docs/design-guidelines.md)を参照する。

## 通常画面と開発用の設定画面

| 表示 | 開き方と役割 |
| --- | --- |
| 独立戦闘デモ（開発／debug版） | `/?debug=1&battle=1`。保存した構図で16:9の戦闘画面を表示。画面の縦横比に応じて余白を設け、構図を保つ |
| 構図設定 | `npm run dev`で`/?debug=1&edit=1`。右上の「構図設定」からも入れる。数値入力・スライダーを動かすと即座に描画へ反映 |
| 画面だけで確認 | 設定画面のボタンで操作パネルを隠し、編集中の構図を通常表示と同じ大きさで確認。「設定に戻る」で編集を続ける |
| 配布用ビルド | 保存したJSONの構図を使う。設定UI・設定画面へのリンク・保存APIを含めない。`?debug=1&edit=1`も無視する |

## 通常画面の戦闘UI

戦闘UIは16:9の盤面上に重ねて表示する。デスクトップでは盤面の大きさに合わせてUIも拡大し、文字・操作部品に読みやすい最小寸法を保つ。幅900px以下では16:9の戦闘ステージを先頭に置き、操作UIをその下に縦積みする。基準寸法は1308×728pxで、画面寸法を固定するものではない。実表示サイズで文字、敵との重なり、横スクロールの有無を確認する。

| 領域 | 配置・表示内容 |
| --- | --- |
| 行動順 | 左端の縦リスト。顔アイコンと次の行動までの残り整数tickを表示する。現在の行動者は枠と暗い面で示し、現在行の0値や「行動中」の文字は表示しない。tickの意味は[戦闘仕様](battle.md)に従う |
| コマンド | 右端の縦リスト。本編は習得スキルから行動を選ぶ。味方の入力待ちでない間と演出中は操作を無効にする。通常攻撃コアの直接操作は明示許可したデバッグ・独立デモだけに置く |
| 一時情報 | 行動者のそばに技名、対象のそばにダメージは負号付き数値（例：−16）、回復は数値と「回復」、命中しなかった場合は「外れ」を表示する。上中央の実況通知は表示しない。位置で分かる名前・対象や発番号を重ねない。戦闘不能は対象の退場とHUD、勝敗は結果画面で伝える |
| 味方の状態 | 下部右寄せ。カードは幅230×高さ78px、間隔10pxを基準とし、味方が増えたら左へ展開する。スキル戦闘では疲労・症状の初回表示でHPの位置が動かないよう1行分を予約する。現在の行動者は枠と暗い面で示す |
| 敵の状態・対象 | 敵の名前とHPを敵の上に表示し、選択中の敵にはさらに上側に四面体マーカーを置く。生存中の敵をクリックすると対象を切り替える。同じ敵を再クリックしても選択は解除しない。初期対象と選択対象が倒れた後の対象は、画面上でカメラに近い生存敵から決める。名前札とマーカーは敵の絵を覆わない |

画面サイズの変更や文字の折返しで札の寸法が変わったときは、現在の敵の投影位置と札・マーカーの実寸から配置を更新する。選択マーカーは選択中の敵札の上側に置き、前の寸法で計算した位置を残さない。

敵の撃破演出後は、その敵の画像・名前札・クリック領域を隠す。残った敵は開始時の位置に留め、陣形を詰め直さない。攻撃対象の選択、HP、行動順、勝敗・再戦の表示は戦闘コアの状態と出来事に従う。表示と演出を戦闘結果の計算に使わない。

通常の戦闘画面にカメラスライダーや「プロトタイプ」などのデモ用表示は置かない。開発サーバーの通常表示にだけ、設定画面へ入る小さなリンクを表示する。

## 戦闘の段階表示

単体スキルと敵の攻撃は、行動者そばの技名の入場・滞在、対象位置の着弾、数値のせり上がり・滞在・退場の順に表示する。技名は短い移動とフェード、数値は短い移動・拡縮とフェード、命中光・回復環は拡大と減衰でつなぐ。キャラ全体の拡大・左右揺れ・撃破時の縦潰れは使わず、撃破は形を変えずフェードして退場する。時間は試作調整値で、段階と表示時刻の投影は`src/presentation/battlePlayback.ts`、各表示の補間は`src/web/battleSequence.css`を正本とする。常設HUDとカメラは揺らさない。命中光は新規SVGの放射形、回復は環と十字、外れは文字で区別する。多段・全体も確定イベントの対象・発番号の順を保持し、一つずつ表示する。

コアの確定状態を先に受け取り、入力を止めてイベントを再生する。HUDのHPは表示専用snapshotへ確定イベントのHP結果を代入し、着弾に合わせて更新する。対象の数値もこの着弾段階から表示を開始する。命中・効果・乱数を再計算せず、表示コピーをコアへ書き戻さない。戦闘不能の退場は確定イベントの後だけ行い、結果への進行は描画コールバックに依存しない。追加発症はそのイベントで確定した症状・HP結果を表示し、最大HP低下を敵のダメージと混ぜない。味方への回復・被弾も各自の実投影位置を使う。再生後は確定状態へ揃え、スキルの対象別結果・発番号・疲労差分を静止した記録に残す。

演出速度は1倍・2倍・即時を選べ、再生中も省略できる。1倍・2倍の変更は次の段階から適用し、現在の段階では補間と待機に同じ速度を保持する。省略は現在と残りの表示待ちだけを解放する。reduced-motionでは移動・拡縮・着弾の拡大を省き、行動者・数値を静止表示する読み取り時間は残す。離脱時は待機と表示を破棄し、旧再生から新しい戦闘へ反映しない。スキル使用中の連打は確定操作を追加しない。これらの表示操作はゲーム時間・疲労・HP・乱数を消費しない。

## 調整・保存・共有

1. カメラの初期位置（左右・高さ・前後）、注視点（左右・高さ・前後）、画角を調整する。
2. 地面の倍率、遠景の倍率・左右・高さ・前後、味方・敵の隊列中心と隣への左右差・前後差を調整する。遠景は垂直な板のまま、縦横比を保って拡大する。確認人数は1人／2人を陣営ごとに切り替えられる。
3. 「画面だけで確認」で構図を確認する。広い調整範囲を許しているので、板の端・接合部・キャラの全身と足元は設定ごとに確認する。地面外の配置は警告される。
4. 「標準として保存」で[`src/web/battle-settings.json`](../src/web/battle-settings.json)へ書き込む。地面外の配置が一つでもある場合は保存できない。通常表示・次回起動・次回ビルドの初期値になる。このJSONをコードと一緒にGit管理する。

未保存の調整は同じブラウザ・同じオリジンのlocalStorageへ一時保存し、設定画面の再読み込み時に復元する。通常表示は一時保存を参照しない。「保存済みに戻す」は最後に保存した標準へ戻し、一時保存を削除する。「JSONを書き出す」は編集中の設定をダウンロードする。別端末への共有や保管にも使える。

保存中は入力を止め、成功したときだけ標準のスナップショットを更新する。失敗時は編集中の値を保ってエラーを表示する。localStorageが使えない場合は一時保存できないことを伝え、ファイルへの標準保存は利用できる。

## 設定と責務

| ファイル | 役割 |
| --- | --- |
| `src/web/battle-settings.json` | 現在の地面モデルと遠景画像の組み合わせに対する構図の正本。形式バージョン2と20個の数値。旧v1は読み込み時に隊列の既定値を補う |
| `src/presentation/battleSettings.ts` | 入力項目、数値範囲、検証。DOM・Babylon.jsを使用せず、UIと保存APIで共用 |
| `src/presentation/battleLayout.ts` | 素材の寸法、基準倍率、中心＋差分からの隊列XZ計算など描画固有の定義 |
| `src/web/battleScene.ts` | 同じシーンへの設定反映、地面レイによる接地高取得、描画、リソース解放 |
| `src/presentation/battleEditorModel.ts` | raw入力・draft・保存待ち・focus・接地結果からの保存可否 |
| `src/web/battleEditor.ts` | 確定した設定UIの描画、Storage・JSON出力・保存API・実接地測定の接続 |
| `scripts/battle-settings-plugin.ts` | Vite開発サーバー専用の保存API。固定ファイルへ書き込み、編集中のプレビューを維持する |

保存APIは同一オリジンのJSON POSTだけを受け、書き込み先を構図JSONに固定する。入力の形式・数値範囲・カメラと注視点の分離を検証する。一時ファイルを書いてから置き換え、途中のJSONを読ませない。モデルや画像を保存操作で変更することはない。

## フィールドごとの設定

構図は全フィールド共通にしない。地面モデルと遠景画像の組み合わせごとにカメラ・倍率・位置・重なりを設定し、既存フィールドの設定を保持する。現在の`src/web/battle-settings.json`は1フィールド分の構図の正本である。

キャラの立ち位置は陣営ごとの「中心＋隣への差分」で決める。人数`n`、配置順`i`（0始まり）から
`x = centerX + (i - (n - 1) / 2) * stepX`、`z = centerZ + (i - (n - 1) / 2) * stepZ`で導出し、
座標配列は保存しない。エディターでは1人・2人を切り替えて同じルールを確認できるが、標準保存時の
地面外検査は固定2対2の全配置枠に対して行う。戦闘不能による詰め直しは行わず、戦闘開始時の配置枠を保つ。

## 素材と描画

右手座標系でYを上とし、カメラは+Z側から-Z方向を見る。地面はGLBを基準26倍で表示し、設定の地面倍率を適用する。遠景は縦横比を保った垂直な板に貼る。キャラの足元は地面メッシュへの下向きレイで求めた接地高に置く。地面外の配置は保存できない。

地面の倍率を変えると、隊列のXZと地面の高さを同じ倍率で再計算する。立ち絵・影の大きさは固定し、遠景とカメラの設定も独立している。確認人数を1人にした場合はその陣営の中心枠へ移し、非表示の枠も標準保存時には地面外検査する。

キャラはY軸だけのビルボードとし、接地影は足元の半透明楕円で示す。キャラと遠景は画像の色をそのまま使い、地面はGLBのPBR材質と照明を使う。素材の出典・利用条件・透過処理は[素材メモ](../art-src/README.md)を参照する。

地面の裏面カリングは、内容を照合できる既知の地形と、画像確認した既定構図・小さいカメラ移動範囲だけに適用する。対象素材と構図条件の正本は[`groundCulling.ts`](../src/presentation/groundCulling.ts)とする。設定の適用・プレビューで条件を再評価し、範囲外、地形内部の視点、別素材、同じパスの別内容、照合不能では素材本来の描画設定を使う。エディタの設定値を制限せず、GLB、PBR、解像度を変えない。この条件は画像で検証した範囲の指定であり、カメラが地形より上なら任意の地形・視点で安全という判定ではない。

## 読み込み・破棄・負荷

- 実行用素材はViteの`BASE_URL`配下から取得し、配布物にも同梱する。実行時に素材配布サイトへアクセスしない。
- GLB・PNG・材質の準備完了後に表示する。読み込み失敗時はエラーを表示する。
- 探索中の最初の戦闘でEngine・Sceneを作り、同じ地面と遠景の指定では読込済みの環境を次戦でも使う。指定が変わる場合は旧環境を解放して入れ替える。現在は既存の1環境だけを使い、ノード別素材や設定形式は追加しない。
- キャラ・材質・接地影・演出・戦闘UIは戦闘ごとに作り、ルートへ戻る際に解放する。旧戦闘の非同期完了や演出が次戦の表示へ作用してはならない。準備待ちは現戦闘に必要な素材だけを対象にする。
- 探索退出で環境・Scene・Engineを解放する。単独の戦闘画面と設定画面は、自身の画面破棄時に全描画資源を解放する。
- 画面破棄とVite HMRでイベント・ResizeObserver・描画ループ・Scene・Engineを解放する。履歴キャッシュへの退避時は画面を維持する。
- 地面モデルは削減・圧縮しない。静止中の再描画を避け、ピクセル比を最大1.5に制限する。設定変更ではモデルを読み直さず、既存オブジェクトの配置・拡大率だけを更新する。
