# 行動完了の生活時計と街回復

`src/game/time.ts` の生活時計は、物語上の経過 `elapsedHalfDays` と回復対象の街行動数 `recoverySteps` を別に保持する。日付差から回復を推測しない。初期表示は1日目・昼。経過0→1→2半日で1日目昼→1日目夜→2日目昼となる。

| 完了した行動 | 生活時計 | 回復step |
| --- | --- | --- |
| 非戦闘の街探索1回 | 半日 | 1 |
| ダンジョン探索1回全体（途中退出を含む） | 半日 | 0 |
| 探索内部のノード移動・会話・戦闘 | 進めない | 0 |
| 編成・メニュー・状態の参照／復元・実時間待ち | 進めない | 0 |

現行の物語上の所要時間は `ACTION_HALF_DAYS = 1` の暫定値。回復stepは時計の差分とは独立した街行動の通知単位で、所要時間の調整だけで回復回数を増やさない。時間帯表示は `getCalendar` から導く。実時間・時間未満の時計・オフライン経過は扱わない。

## 行動と完了ID

`beginTimedAction` が単調増加IDと行動種別を持つ未完了行動を一つ作る。開始だけでは時間・回復を進めない。未完了行動がある間は次の行動を開始しない。`completeTimedAction` は現在のID・種別が一致するときだけ一度計上し、未完了を解除する。完了通知にはID・種別・生活経過量・回復step数を返す。完了再送、古いID、違う種別は通知を出さず二重計上しない。

## セッションへの接続

`src/game/expedition.ts` の `ExpeditionGame.clock` がセッションの正本。省略した新規状態は初期時計として扱う。

- `beginTownExploration` が街の場所を選び、非戦闘の会話を開始する。PT人数・戦闘参加可能性を条件にしない。
- `actInTown` は行動IDと文章送り／選択を受け取る。会話が街へ戻ったときだけ `completeTownExploration` で完了を計上する。途中の文章・選択・無効入力では計上しない。
- 街完了は[状態異常](status.md)の回復signalを一度だけ送る。回復signalのIDは既存の回復watermarkを引き継ぎ、行動IDとは独立して採番する。加入済み全キャラについて回復前後の状態と種類別の残りstepを返す。街2回で生活1日・回復2step。街→探索→街で生活1.5日・回復2step。
- `departOnExpedition` は探索行動を開始し、`leaveExpedition` が全体の半日を一度計上する。探索開始、ボス勝利、ノード終了では生活時計を動かさない。退出の再配送を扱う接続側は開始時IDを `leaveExpedition` へ渡す。古い退出IDで次の探索を終えない。
- 探索の生活経過は誰の症状にも回復signalを送らず、控えの回復も進めない。控えだけ街滞在を計上する例外は未確定。

街で新規発症と同じ行動の回復が重なる順序は未確定。発症操作・完了操作は呼ばれた順序で適用する。完成した街イベントの統合側が順序を選ぶまで、時計自身から新規発症しない。

## 統合の責務

通常ブラウザの街会話は街探索ラッパーへ入力を渡し、加入イベントを含む街探索完了を一度計上する。会話配置エディタは時計のない会話プレビューを維持する。街・編成・ルートには `getCalendar` から導いた日数と昼夜を表示する。探索内部では同じ表示を維持し、帰還後の街で更新する。街探索完了では症状の数値変化と残り街探索回数を表示し、変化のない仲間を結果へ並べない。編成の開閉・画面の再描画は参照だけを行う。新規発症のイベント順序は街イベントの統合側が決める。

全員戦闘不能でも街探索を完了して回復stepを得られる。戦闘不能解除後もHP0なら出撃を拒否する。HP回復は帰還処理の責務で、時計は無料蘇生・新しい休息／治療コマンドを追加しない。

精神疲労の連続数値・回復量・効果曲線は精神疲労側の正本。受理した街完了通知のIDと回復stepを使って一度だけ数値更新を接続する。時計に独立した精神疲労段階や数値曲線を持たせない。

時計・未完了ID・回復状態はメモリ上のセッションに保持する。ゲーム保存・復元のI/Oや移行は保存機能の担当で、この仕様だけで永続保存可能とは扱わない。
