# UIデザインガイドライン

`endfield_rpg`は、『アークナイツ：エンドフィールド』の二次創作として制作する、ブラウザ向けのコマンド式RPGである。本書は、ボタン、ウィンドウ、状態表示、アイコンなどのUIを追加・変更するときに、見た目と操作状態の表現を統一するための基準を定める。AIで生成するUI用画像にも適用する。

本書が扱うのは画面表現であり、戦闘ルールや機能の実装状況ではない。戦闘ルールは[戦闘仕様](battle.md)、背景・キャラクターの配置は[画面・構図仕様](visuals.md)、素材の出典と利用条件は[素材メモ](../art-src/README.md)を参照する。

## 1. デザインコンセプト

> 未来の辺境を旅するための、静かなコマンドRPGの窓。煤色の平らな面と、鈍い金属の細い罫線で物語の落ち着きを保ち、いま判断する対象だけを明確にする。

工業製品や鉱物を連想させる意匠を、縦型コマンドなどの読みやすい画面構成に組み合わせる。背景とキャラクターを主役にし、常設UIは控えめにする。強い色や動きは、操作対象へ注意を向けるために限定して使う。

大きな金色の面、厚い金縁や立体的な盛り上がり、中世風の唐草、宝石、過剰なネオン、意味のない管理番号は使わない。

## 2. テーマと配色

色は「主役の色・脇役の色」ではなく、下地・文字・操作・データなどの用途で指定する。用途ごとに名前を付けた変数を**色トークン**と呼ぶ。例えば、`text.primary`は主文字、`action.primary`は主操作を表し、同じ`primary`でも役割は異なる。

CSSでは、色そのものの定義 → 用途ごとの変数 → UI部品の順に参照する。色トークンの定義の正本は[実装CSS](../src/web/style.css)の`:root`とし、値を変えるときは本書の表も同期する。

| 用途 | CSS変数 | 色 | 使用ルール |
| --- | --- | --- | --- |
| 基調面 | `--surface-base` | `#232825` | パネルやボタンの下地。文字の下は不透明にする |
| ホバー面 | `--surface-hover` | `#313B34` | ポインターが重なった操作部品の下地 |
| 選択面 | `--surface-selected` | `#3C463E` | 選択中も暗い下地を維持する |
| 押下面 | `--surface-pressed` | `#171D19` | 押下中の下地 |
| 主文字 | `--text-primary` | `#ECE9DF` | 本文、コマンド、主要数値 |
| 補助文字 | `--text-secondary` | `#B8C1B9` | 補足、単位、待機表示 |
| 金属罫線 | `--trim-metal` | `#B58A46` | 細い装飾罫や選択枠。主文字の下地には使わない |
| HP | `--data-hp` | `#91B9A8` | HPなど、落ち着いて読むデータ |
| 主操作 | `--action-primary` | `#F0B84A` | 情報量の少ない確認・出撃画面の主ボタン |
| 主操作上の文字 | `--on-action-primary` | `#232825` | 琥珀色の主ボタンに載せる文字 |
| 選択マーカーの稜線 | `--selection-edge` | `#F0B84A` | 小面積で操作対象を強調する |
| 危険表示 | `--status-danger` | `#ED927F` | ラベルや形を伴う警告 |

補助文字は文字の優先度を表すもので、別の情報カテゴリーを色分けするためのものではない。文字サイズ・配置・ラベルも併用する。HPの緑は注意を引く装飾に転用せず、大きな琥珀色の塗りは情報量の少ない画面に限定する。HPバーの下地には`--data-track: #313B34`を使う。

### コントラスト

コントラスト比は、文字や図形と下地の明るさの差を数値化したもの。通常文字は**4.5:1以上**、操作や状態の識別に必要な非テキスト部分は**隣接色と3:1以上**を基準とする。装飾だけの罫線ではなく、実際に情報を伝える前景と下地の組み合わせを確認する。基準の詳細はW3Cの[文字のコントラスト](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)と[非テキストのコントラスト](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)を参照する。

| 前景 / 下地 | 用途 | コントラスト比 |
| --- | --- | ---: |
| `#ECE9DF` / `#232825` | 主文字 / 基調面 | 12.33:1 |
| `#ECE9DF` / `#3C463E` | 主文字 / 選択面 | 8.09:1 |
| `#B8C1B9` / `#3C463E` | 補助文字 / 選択面 | 5.32:1 |
| `#232825` / `#F0B84A` | 主ボタンの文字 / 下地 | 8.32:1 |
| `#91B9A8` / `#313B34` | HPバー / バーの下地 | 5.38:1 |
| `#B58A46` / `#3C463E` | 選択枠 / 選択面 | 3.13:1 |
| `#F0B84A` / `#171D19` | マーカーの稜線 / 暗い外縁 | 9.51:1 |

上表は不透明な単色同士をsRGBの相対輝度から計算した値で、小数第2位まで表示している。合否は丸め前の値で判定する。透過や画像を下地に使う場合は合成後の色で再確認する。マーカー内部のコントラストが確保できても、背景上で見つけやすいとは限らないため、実画面でも確認する。

## 3. 部品の形・文字・操作状態

形は直角を基本とし、薄い二重罫と控えめな真鍮色で統一する。大きな角丸や厚みのある装飾は使わない。見出し・コマンドは控えめな明朝体、説明はゴシック体、比較する数値は等幅を基本とする。文字や数値は画像に焼き込まない。

操作部品には、通常・ホバー・押下・選択中・フォーカス・使用不可を用意する。**選択中**は選んだ内容、**フォーカス**は次のキー入力を受け取る場所を表し、別々に識別できるようにする。選択は暗い面と罫線、フォーカスは白い外枠で示す。使用不可は見た目だけでなく操作も無効化し、鍵の印などを添える。状態を色だけで伝えない。

## 4. 四面体の選択マーカー

選択マーカーは、枠だけでは位置を示しにくい操作対象を指すための部品である。形は、原作の「協約オリジニウム」をモチーフにした、4枚の三角形の面からなる立体とする。頂点を回転・投影し、奥行き順に面を描いて立体感を保つ。暗い面、等高線状の刻み、琥珀色の稜線で表現し、小さい表示では刻みよりも輪郭を優先する。

**同じゲーム画面全体で原則1個、同時に最大2個まで。静止中も数に含める。** 枠やラベルで識別できる場所には重ねず、注意を向ける先を増やさない。

| 場所・状態 | 表示ルール |
| --- | --- |
| 行動順、味方カード、コマンド | 表示しない。枠と文字で状態を伝える |
| スキル説明、攻撃通知 | 表示しない。選択対象ではなく情報表示として扱う |
| 敵の対象選択 | 選択対象の上に1個表示する |
| 防御や攻撃通知中など、対象を選ばない状態 | 表示しない |

複数の敵をまとめて対象にする場合は、一体ずつマーカーを付けず、範囲枠などを使う。別の選択操作に導入する場合も、必要性と画面全体の個数上限を確認する。縦に並ぶ対象では左、横に並ぶ対象では上に置き、先端を対象へ向ける。

回転は、平面のひし形を回すのではなく、立体の頂点を投影して長軸の周りに6秒で1周させる。動きは補助であり、低いコントラストを補う手段にはしない。OSの「動きを減らす」設定を示す`prefers-reduced-motion: reduce`に対応し、設定時は静止させる。静止中も輪郭と対象名で選択が分かること。実装時はW3Cの[動きを減らす設定への対応](https://www.w3.org/WAI/WCAG22/Techniques/css/C39)を参照する。

## 5. AIでUI用画像を制作する手順

文字・数値・操作状態・単純な枠・寸法はHTML/CSS/SVGで管理し、AI生成は追加の図案や質感に使う。ボタンを文字ごと生成したり、状態ごとに別の形を作り直したりしない。

生成時は、本書と制作対象に近い既存のUI素材をAIに渡し、両方を参照させる。本書を配色・状態表現などのルール、既存素材を輪郭・線幅・質感・余白の見本として使う。適切な既存素材がない場合は、[実装CSS](../src/web/style.css)と実画面のスクリーンショットを見本にする。

依頼では、作る部品の用途、実際の表示サイズ、背景透過の要否、必要な状態差分、既存素材から変更したい点を指定する。共通のデザインルールは本書を参照し、依頼ごとに書き直さない。

生成後は既存素材と並べ、色・寸法・透過・余白・質感の統一を確認する。色がずれている場合は、該当するトークン色へ補正する。状態差分は同じ原画から作り、輪郭や余白を変えない。実表示サイズで見え方を確認してから採用し、出典・利用条件を[素材メモ](../art-src/README.md)に記録する。

実画面へ適用した後、想定する表示サイズと背景で文字・状態が読み取れ、選択・フォーカス・使用不可を識別できることを確認する。OSで動きを減らした場合も、操作対象を判別できる必要がある。これらの確認だけでWCAGの全要件を満たしたとは判断しない。
