# テスト設計

ゲームのルール、画面の見た目、操作から結果までの接続を、それぞれ最も安定して検証できる場所で担保する。Issue [#11](https://github.com/karin0624/endfield_rpg/issues/11)のブラウザテストはChromiumに絞る。

| 対象 | 方法 | 担保すること |
| --- | --- | --- |
| ゲーム本体と描画に依存しない計算 | Node環境のVitest（`npm run check`） | 行動順、攻撃、HP、勝敗、再戦、設定値の検証・移行、隊列計算。実時間やブラウザを使わず分岐を確認する |
| 静的な見た目 | 固定コンテナ内のPlaywright VRT（`npm run test:e2e`） | 実際のBabylon.js、WebGL、GLB・PNGを読み込んだ初期戦闘画面を代表的な画面幅で画像比較する |
| 操作・接続 | Playwrightの挙動アサーション（`npm run test:e2e`） | 実ボタンでの対象選択、攻撃、HP更新、勝利、再戦を確認する |
| 構図設定の保守 | 必要時だけ実行するPlaywright（`npm run test:editor`） | 設定画面のVRT、編集・保存・復元、保存APIを確認する。通常のCIには含めない |

静止画で確認できる要素の存在・配置を個別のDOMアサーションで重複させない。画像に写らない状態変化や操作の意味は画像比較に任せない。戦闘ルールの分岐をブラウザで網羅しない。`page.evaluate`で戦闘状態を直接変更せず、ゲーム本体と本番の入力経路を使う。

VRTの基準画像はPlaywrightのバージョンを固定した公式コンテナ内で生成し、同じ環境のCIで比較する。Chromiumのソフトウェア描画、画面寸法、device scale、視差効果の設定を固定する。基準画像はレビューしてから更新し、差分を許容する設定で大きな欠損を隠さない。描画の準備完了だけで成功とせず、実際の画像比較、素材のHTTPエラー、ページエラーも確認する。WebGLが使えない場合は失敗として報告する。

ローカルからは`npm run test:e2e`または`npm run test:editor`がコンテナを起動する。コンテナ外でPlaywrightを直接起動した場合は設定の読み込み時に失敗させる。CIのコンテナジョブは`npm run test:e2e:inside`を使う。基準画像更新時のコマンドは[README](../README.md)を参照する。

各E2Eケースは独立した初期画面から始める。`test:e2e`では常に`prefers-reduced-motion: reduce`を指定して演出の待ち時間を省き、確定後の結果を確認する。待機はPlaywrightの再試行付きアサーションで画面の状態変化を待ち、固定秒数のsleepを使わない。アニメーションの見た目を検証する必要が生じた場合は、静止画VRTとは分けて安定した観測方法を設計する。失敗時はスクリーンショットとトレースを保存する。`npm run check`ではブラウザを起動せず、CIのブラウザジョブは短い接続確認だけを実行する。
