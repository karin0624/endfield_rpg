# 仕様概要

この文書は[Issue #1](https://github.com/karin0624/endfield_rpg/issues/1)の合意事項と暫定案を整理した仕様の入口。作業規約は[AGENTS.md](../AGENTS.md)、実装順は[マイルストーン](milestones.md)を参照する。

## 合意済みの要件

| 項目 | 方針 |
| --- | --- |
| 実行環境 | ブラウザ。将来の頒布形式は未定 |
| 開発方針 | Codex中心で実装する。描画なしの機械的・高速なテストと、必要最小限の実装を優先する |
| 進め方 | 依頼1本を通して遊べる試作から始め、試遊結果を見て一つずつ機能を追加する |
| 戦闘 | 速度によるタイムライン式。順番が来た味方ごとに行動を選択し、入力中は論理時刻が止まる。ラウンド冒頭に全員分をまとめて入力する方式ではない |
| 街・拠点 | 場所を選ぶADV形式。会話、選択肢、フラグによるイベント分岐を扱う |
| ダンジョン | 分岐・合流のあるルートから次のノードを選択する。キャラクターを歩かせる探索は作らない |
| 戦闘画面 | キャラ・敵は2D、地面は3D、遠景は2D背景画像。立体的な床とカメラ表現を使う。背景全体の3D化は不要 |

### 参考作品の位置づけ

ユーザー指定の参考は、企画・体験が『パワポケ12 裏サクセス 秘密結社編』、戦闘の見た目が『オクトパストラベラー』、行動順が『崩壊：スターレイル』、ルート選択が『Slay the Spire』。

これらは方向性の参考であり、全システムや数式の完全再現を要求しない。原作の文章や素材はコピーせず、試作用の内容を用意する。

## 採用する技術と責務

以下は採用方針。TypeScript、Vite、Vitestによる最小構成と各ディレクトリの境界はIssue #3で導入済みであり、個別のゲーム機能と描画技術は該当Issueで追加する。

| 領域 | 構成 |
| --- | --- |
| 開発 | TypeScript＋Vite。初期段階ではUIフレームワークを追加しない |
| ゲーム本体 | `src/game/`に状態・ルール、`src/content/`に型付きの定義データを置く |
| ブラウザ | `src/web/`にBabylon.jsの描画と入力・演出・保存I/Oを置く |
| 画面UI | 会話・街・戦闘コマンドはHTML/CSS。ルート図はHTMLボタンと必要に応じたSVG |
| 主な検証 | VitestのNode環境でゲーム本体を直接実行する |
| 接続の検証 | Playwrightで実ボタンから入力し、画面とゲーム本体の接続を少数ケースで確認する |

上記のディレクトリは該当する実装の着手時に作る。文書整備だけの段階に空のソースディレクトリは作らない。

### ゲーム本体と表示の境界

ゲーム本体は通常のオブジェクト・配列と同期処理で「状態＋操作→次の状態＋出来事」を扱う。DOM・描画エンジン・通信・実時間・保存I/Oから独立させ、描画オブジェクトをゲーム状態に持たせない。

ブラウザとテストは同じゲーム本体を使う。UIは確定済みの結果を表示し、ゲームルールや論理状態の別の正本を持たない。演出用の一時状態は持てるが、演出終了をルール確定の条件にしない。

乱数が必要になった場合はゲーム状態に乱数状態を保持し、同じ初期状態・操作列で結果を再現できるようにする。演出用乱数とは分ける。

ゲーム本体の検証では、描画も実時間待ちも必要としない。ブラウザの接続テストでは実際の入力経路を通す。初期状態のフィクスチャや依存のモックは利用できるが、検証対象の処理や結果そのものを代替して成功扱いにしない。

## 最小試作の暫定案

以下は試作を進めるための開始案であり、ユーザーが確定した製品版仕様ではない。変更時は理由を記録し、関連する仕様・実装・テスト・Issueを整合させる。詳細は該当Issueの着手時に仕様化する。

| 項目 | 開始案 | 詳細化するIssue |
| --- | --- | --- |
| 編成・戦闘 | 味方2人・敵2体、通常攻撃のみ。固定ダメージ、命中・防御・乱数なし | [#7](https://github.com/karin0624/endfield_rpg/issues/7)、[#8](https://github.com/karin0624/endfield_rpg/issues/8) |
| 行動順 | 戦闘中は速度固定。行動間隔と同時刻の優先順位は#6の暫定案を仕様化する | [#6](https://github.com/karin0624/endfield_rpg/issues/6) |
| 探索 | 分岐と合流を含む手書きの固定ルート1つ。探索中のHP・戦闘不能を次戦へ引き継ぐ | [#14](https://github.com/karin0624/endfield_rpg/issues/14) |
| 依頼 | 依頼1本。成功後の報告で固定報酬を1回だけ得る。失敗時は報酬なしで再受注可。帰還時に全回復する | [#16](https://github.com/karin0624/endfield_rpg/issues/16) |
| 保存 | 街の通常画面で1スロット保存。会話・戦闘・探索途中の保存はしない | [#17](https://github.com/karin0624/endfield_rpg/issues/17) |
| 会話表示 | 本文は一括表示。バックログ、既読管理、オート再生、ボイスは初期範囲に含めない | [#12](https://github.com/karin0624/endfield_rpg/issues/12)、[#13](https://github.com/karin0624/endfield_rpg/issues/13) |
| カメラ・構図 | 地面モデルと遠景画像の組み合わせごとに、初期カメラ・倍率・重なりの固有設定を持つ。現在は1フィールド分を開発用画面で調整・保存する。別フィールドの追加時に設定も分け、既存の採用値を保持する。操作UIは配布画面に含めない | [#4](https://github.com/karin0624/endfield_rpg/issues/4)、[#5](https://github.com/karin0624/endfield_rpg/issues/5)、[画面仕様](visuals.md) |

Issue #4・#5で提供済みファイルを確認し、実際の戦闘画面へ取り込んだ。配置・確認画面は[visuals.md](visuals.md)、出典と利用条件の確認状況は[素材メモ](../art-src/README.md)を参照する。

| 素材 | 状況と初期の扱い |
| --- | --- |
| 主人公 | 提供PNG5方向の白背景をユーザーの指定で透過化。斜め左前1枚を使用し、他4方向を`art-src/`に保管 |
| 地面 | TripoのGLB（約56 MiB・テクスチャ内包）を使用。26倍で配置し、Git LFSで管理 |
| 遠景 | 提供された2138×736のGPT Images背景を垂直な板に貼り、地面の奥に重ねて配置 |
| 敵 | Issue #4・#5と合わせてKenneyのCC0ブルースライムを先行導入。仮敵1体として表示 |
| 追加の味方・NPC・街背景 | 素材の用意は未確認。必要な箇所だけ仮表示にする |

敵素材の導入・出典記録は先行実施したが、[Issue #10](https://github.com/karin0624/endfield_rpg/issues/10)自体の完了判定は今回行わない。追加の素材待ちでゲーム本体の開発を止めない。実行用は`public/assets/`、未使用の方向画像は`art-src/`に置く。
