# 仕様概要

この文書は[Issue #1](https://github.com/karin0624/endfield_rpg/issues/1)の合意事項と暫定案を整理した仕様の入口。作業規約は[AGENTS.md](../AGENTS.md)、実装順は[マイルストーン](milestones.md)を参照する。

## 合意済みの要件

| 項目 | 方針 |
| --- | --- |
| 実行環境 | ブラウザ。将来の頒布形式は未定 |
| 開発方針 | Codex中心で実装する。描画なしの機械的・高速なテストと、必要最小限の実装を優先する |
| 進め方 | 依頼1本を通して遊べる試作から始め、試遊結果を見て一つずつ機能を追加する |
| 戦闘 | 速度によるタイムライン式。順番が来た味方ごとに行動を選択し、入力中は論理時刻が止まる。ラウンド冒頭に全員分をまとめて入力する方式ではない |
| 街・拠点 | 場所を選ぶADV形式。会話、選択肢、フラグによるイベント分岐を扱う |
| ダンジョン | 分岐・合流のあるルートから次のノードを選択する。キャラクターを歩かせる探索は作らない |
| 戦闘画面 | キャラ・敵は2D、地面は3D、遠景は2D背景画像。立体的な床とカメラ表現を使う。背景全体の3D化は不要 |

### 参考作品の位置づけ

ユーザー指定の参考は、企画・体験が『パワポケ12 裏サクセス 秘密結社編』、戦闘の見た目が『オクトパストラベラー』、行動順が『崩壊：スターレイル』、ルート選択が『Slay the Spire』。

これらは方向性の参考であり、全システムや数式の完全再現を要求しない。原作の文章や素材はコピーせず、試作用の内容を用意する。

### ゲーム本体と表示の境界

ゲーム本体は通常のオブジェクト・配列と同期処理で「状態＋操作→次の状態＋出来事」を扱う。DOM・描画エンジン・通信・実時間・保存I/Oから独立させ、描画オブジェクトをゲーム状態に持たせない。

ブラウザとテストは同じゲーム本体を使う。UIは確定済みの結果を表示し、ゲームルールや論理状態の別の正本を持たない。演出用の一時状態は持てるが、演出終了をルール確定の条件にしない。

乱数が必要になった場合はゲーム状態に乱数状態を保持し、同じ初期状態・操作列で結果を再現できるようにする。演出用乱数とは分ける。

ゲーム本体の検証では、描画も実時間待ちも必要としない。ブラウザの接続テストでは実際の入力経路を通す。初期状態のフィクスチャや依存のモックは利用できるが、検証対象の処理や結果そのものを代替して成功扱いにしない。

以下は試作を進めるための開始案であり、ユーザーが確定した製品版仕様ではない。変更時は理由を記録し、関連する仕様・実装・テスト・Issueを整合させる。詳細は該当Issueの着手時に仕様化する。

| 項目 | 開始案 | 詳細化するIssue |

| 会話表示 | 本文は一括表示。バックログ、既読管理、オート再生、ボイスは初期範囲に含めない | [#12](https://github.com/karin0624/endfield_rpg/issues/12)、[#13](https://github.com/karin0624/endfield_rpg/issues/13) |
| カメラ | 固定アングルを基本に、寄りと小移動まで。床と背景板の接合部は構図や遮蔽物で隠す | [#4](https://github.com/karin0624/endfield_rpg/issues/4)、[#5](https://github.com/karin0624/endfield_rpg/issues/5) |

## 素材の状況

この文書の追加時点では、以下の「用意済み」はユーザーの説明に基づく。実ファイルはまだリポジトリに配置されておらず、形式・見た目・読み込み・利用条件は未確認。

| 素材 | 状況と初期の扱い |
| --- | --- |
| 主人公 | 正面、左右側面、背面、斜め左前の画像を用意済み。まず戦闘用の斜め左前1枚を使う |
| 地面 | ChatGPTで作った画像を元にTripoで生成済み。実行用はGLBを基本とし、実ファイル確認後に必要な変換だけ行う |
| 遠景 | GPT Imagesの2D背景画像を使う。改めて3D背景を調達しない |
| 敵 | 未確定。2Dフリー素材1種の流用、または明示した仮シルエットから始める |
| 追加の味方・NPC・街背景 | 素材の用意は未確認。必要な箇所だけ仮表示にする |

取り込みと画面確認は[Issue #5](https://github.com/karin0624/endfield_rpg/issues/5)、敵素材の導入と出典・利用条件の記録は[Issue #10](https://github.com/karin0624/endfield_rpg/issues/10)で行う。これらの待ち時間にゲーム本体の開発を止めない。将来の素材配置先や編集元の管理方法は、取り込み時に実ファイルに合わせて決める。
