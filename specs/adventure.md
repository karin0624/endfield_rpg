# 街・会話のゲーム本体

Issue [#12](https://github.com/karin0624/endfield_rpg/issues/12)で実装した、街の場所選択と型付き会話データの仕様。全体の境界は[仕様概要](overview.md)、画面側との接続は後続のIssue #13で扱う。

## 状態

`GameState`は次を保持する。

| 項目 | 意味 |
| --- | --- |
| `mode` | `town`または`conversation`。入力できる操作を決める |
| `currentPlaceId` | 街で選んだ場所。会話中と街へ戻った後も選択先を保持する。初期値は`town-square` |
| `conversationId` | 進行中の会話ID。街にいる間は`null` |
| `conversationPosition` | 進行中のノードID。街にいる間は`null` |
| `flags` | 選択や会話完了で立つ文字列フラグ。重複させない |

初期状態は街の広場にいて、会話ID・進行位置・フラグは空。街の場所一覧と会話場面の取得は参照だけを行い、状態を変更しない。

## 操作と状態遷移

| 操作 | 許可条件 | 結果 |
| --- | --- | --- |
| `getAvailableTownPlaces` | `mode === "town"` | 場所の解放条件と会話ルート条件を満たす場所を返す |
| `selectTownPlace` | 街にいて、指定場所が選択可能 | 場所を`currentPlaceId`へ設定し、条件に合う会話の開始ノードへ進む |
| `getCurrentConversationScene` | 会話ID・進行位置が有効 | 現在の文章または選択肢と表示指定を返す |
| `advanceConversation` | 現在位置が文章ノード | 次ノードへ進む。次が終了ノードなら会話を終える |
| `chooseConversationOption` | 現在位置が選択肢ノードで、指定選択肢の条件を満たす | 選択肢のフラグを立てて次へ進む。次が終了ノードなら会話を終える |

会話終了時は`mode`を`town`へ戻し、会話IDと進行位置を`null`にする。`currentPlaceId`は会話を始めた場所のままにする。会話の`onCompleteFlags`は終了時に一度だけ適用し、フラグを重複させない。

無効な場所、街以外からの移動、文章以外への文章送り、選択肢以外での選択、条件未達の選択肢は拒否する。拒否結果は元の状態と同じ参照を返し、フラグなどを変更しない。条件付き選択肢は場面取得時に利用可能なものだけを返すが、コアは直接IDを指定された場合にも同じ条件を検査する。

## 型付き会話データ

`src/content/initialAdventure.ts`の`AdventureDefinition`は場所と会話の配列を持つ。IDは文字列で参照し、`assertValidAdventureDefinition`が場所・会話ID、ノード進行先、選択肢ID・到達先を検査する。

- 場所には`availableWhen`と会話ルートを指定できる。ルートは定義順に最初に条件を満たすものを選び、条件なしの既定ルートを最後に置く。
- フラグ条件は`all`（すべて必要）と`none`（どれも存在してはいけない）だけを使う。
- 会話ノードは文章、選択肢、終了の3種類。文章送りと選択肢はIDで次ノードを指定する。
- 選択肢は`when`で表示・実行条件を持ち、`setFlags`で選択時に立てるフラグを指定できる。
- 文章と選択肢には必要な場面だけ`speakerName`、`backgroundId`、`portraitId`、`expressionId`、`position`（`left`・`center`・`right`）を指定できる。これらは表示用IDであり、素材対応やサイズ・座標は画面側の責務とする。
- 選択肢ノードには最低1つ、条件なしで実行できる選択肢を含める。画面に表示されない選択肢を直接実行することはできない。

## 初期コンテンツと確認例

初期コンテンツには広場・ギルド・市場を用意した。ギルド初回の選択肢で「掲示板の依頼について聞く」を選ぶと`heard-guild-quest`が立ち、会話完了時に`visited-guild`が立つ。再訪では`visited-guild`と`heard-guild-quest`の両方がある場合に依頼の話を続ける会話を選ぶ。依頼の話を選ばずに会話を終えた場合は`visited-guild`だけが立ち、別の再訪会話になる。未取得の`knows-secret`を条件とする選択肢は一覧から隠れ、直接指定しても拒否される。

ゲーム本体のテストは`npm run check`に含まれるNode環境のVitestで、場所選択から会話終了・再訪分岐・拒否・データ参照の検査まで確認する。ブラウザ画面の表示と入力接続はIssue #13の範囲。

## ブラウザ画面

通常の`/`は街を表示する。場所ボタンは`getAvailableTownPlaces`の結果から作り、押下時は`selectTownPlace`へ渡す。文章場面は画面クリックまたはSpaceで`advanceConversation`を呼び、選択肢場面では各ボタンまたは表示番号の数字キー・テンキーから`chooseConversationOption`を呼ぶ。選択肢場面で画面クリックやSpaceを使って先へ進めない。会話終了後はコアの状態に従って街へ戻り、再訪時の会話も同じコアの条件分岐を使う。

背景ID、立ち絵ID、表情ID、左右・中央・右の位置は会話データから表示だけに使う。ギルド会話はロッシとギルベルタの正面立ち絵を表示する。話者の立ち絵を明るく、同じ会話に登場する別の立ち絵を暗く表示する。選択マーカーは左から対象を指す、静止した四面体。Auto、Menu、Spaceの表示は設けない。戦闘画面は街の「戦闘デモを見る」リンクか`/?battle=1`で引き続き開ける。

開発サーバーの`/?adventureEdit=1`で会話画面の配置を調整できる。左・中央・右の水平位置と全員共通の立ち絵の足元・高さ、本文パネル・話者名・本文・送り矢印・選択肢の位置を、横画面と縦画面の必要な項目ごとに設定する。調整中はプレビューへ即時反映し、ブラウザには未保存の下書きを保持する。「標準として保存」で`src/web/adventure-settings.json`に保存すると、通常画面と配布ビルドの標準になる。設定画面と保存APIは開発サーバーだけで使える。

プレイヤー向け文字は[デザインガイドライン](design-guidelines.md)の用途別サイズを使う。
