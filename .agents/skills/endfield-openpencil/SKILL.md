# OpenPencilで既存.figを編集する

導入・接続・コマンドは[README](../../../README.md#openpencilでfigを編集する)を正本とする。まず指定されたファイルとGit差分を確認する。対象が不明なら既存の`.fig`を探し、対象が複数なら本人へ確認する。導入確認のためにHomeなどの画面を作り直さない。

## 同じPCのアプリをMCPで編集する

1. `list_documents`で開いている文書とページを確認する。既に対象が開いていればそれを使い、未保存の本人編集を閉じたり上書きしたりしない。
2. 未開封なら`open_file`にrepoからの対象パスを渡す。返された`document_id`と対象`page_id`を以後の呼び出しへ明示する。
3. `get_page_tree`と`get_node`で現在のレイヤーを読み、依頼範囲だけ変更する。通常は`update_node`、`set_fill`、`set_text`などの専用ツールを使う。
4. `save_file`へ同じ文書IDと保存先を明示し、保存後にCLIで同じファイルを読み直して変更を確認する。`git diff --stat`と対象パスを確認して引き継ぐ。

接続できないときはアプリの起動、Settings → MCPの状態・版・対象フォルダーと、同じPC／ユーザーで実行しているかを確認する。認証を無効化したり、永続許可・Tool access・選択限定の設定を勝手に広げたりしない。接続エラーを空文書の作成で代替しない。

## アプリがない実行環境

CLIへファイルパスを渡すとheadlessで読取・編集・保存できる。先に`info`／`tree`で対象を読み、`eval`の`--output`で別ファイルへ保存して再読取する。原本への`--write`は対象と既存差分を確認してから使う。これはローカルファイル操作で、本人PCの開いているタブへは反映しない。CLIの`eval`のためにMCPの`eval`を有効化する必要はない。

画面の設計変更・製品への反映は既存の[画面設計と制作手順](../../../AGENTS.md)に従う。`.fig`の保存成功を外観確認・本人承認・製品実装の完了と扱わない。
