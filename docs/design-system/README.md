# 本作のUIデザインシステム

UIの判断、表現、部品、画面の組合せ、制作と検証を辿る索引である。既存実装値や未承認提案を完成デザインとして扱わず、対象の仕様と承認範囲を確認する。

| 確認したいこと | 正本 |
| --- | --- |
| 必要性・共通視覚言語・到達性・承認範囲 | [UIデザイン原則](principles.md) |
| 色・文字・余白・形・図案・動きの用途と選び方、現在値への接続 | [基本デザイン](foundations.md) |
| 再利用する部品の目的・構造・variant・状態・入力・例外 | [共通部品](components.md) |
| 画面の構図・階層・グルーピング・配置・操作とパターン | [画面設計とパターン](screens-and-patterns.md) |
| 部品・画面・制作から検証へ通す共通要件 | [アクセシビリティ](accessibility.md) |
| 指摘・調査・仮説・要因別比較・制作・承認・製品確認 | [制作・検証手順](production-and-validation.md) |
| 既存画面と部品・実装・適用範囲の対応 | [適用一覧](adoption.md) |

ゲームの振る舞いは[specs](../../specs/overview.md)、検証層と実行コマンドは[テスト設計](../testing.md)、進捗・受入条件・承認は対象Issueを正本とする。文書責務の判断は[ADR 0012](../adr/0012-ui-document-responsibilities.md)。設計図や説明画像は必要な文書の近くへ置けるが、参照原本・Spaceの正式保存・公開範囲を[文書規則](../documentation.md)から引き継ぐ。未承認の試作を正式な実行素材へ移さない。

構成は[デジタル庁](https://design.digital.go.jp/dads/)、[SmartHR](https://smarthr.design/)、[Material 3](https://m3.material.io/)等の責務分離を参照し、本作の目的と入力・画像承認へ対応付ける。各社の色・寸法・focus意匠・全component・組織審査を一括導入するものではない。
