# UIデザイン原則

本書は画面を評価する共通原則である。[基本デザイン](foundations.md)は表現の役割、[共通部品](components.md)は再利用する構造と契約、[画面設計](screens-and-patterns.md)は画面を組み立てる方法、[制作・検証手順](production-and-validation.md)は根拠から制作・承認・確認へ進む方法を扱う。ゲームの振る舞いは[specs](../../specs/overview.md)、適用済み範囲は[適用一覧](adoption.md)、横断要件は[アクセシビリティ](accessibility.md)を参照する。

## 判断と操作から必要性を決める

情報は0個から考え、各要素に「この画面に無いとどの判断・操作に困るか」を対応付ける。重複だけでなく、意思決定に寄与しない表示を取り除く。文字なしで成立する構造を先に検討し、必要な識別名・数値・操作名・制約・結果・読み上げ情報は明確に伝える。必要な情報を隠すための原則にはしない。

背景を大きく見せること、既存配置を保つこと、共通CSSへ揃えること自体を目的にしない。仕様の操作可能な時点と、その入口を常設する必要性は別に判断する。準備中だけに管理操作を限定する等、配置の都合で規則を作らない。

文言も一語ごとに必要性を確認し、識別に足りる名称へ無意味な修飾を加えない。文字数だけを指標に、操作名・危険の説明・制約を削らない。既存文言を残すことと削ることの双方に根拠を求める。

## 共通の視覚言語を優先する

同じ役割・階層の操作は共通部品を基本とし、枠、面、余白、ラベル、状態反応を揃える。新しい部品や例外は、目的・情報・入力・承認意匠が既存部品では満たせない理由を示して採否を判断する。既存の実装値は比較する現状であり、未承認画面の配置や寸法を決める根拠にはしない。

同じ操作階層の入口を、根拠なく一つだけ目立たせない。図案内で意味を識別する色と、主操作・選択・危険を示す色を区別する。色数を減らすことや多色にすることだけでは読みやすさを保証できない。形、ラベル、実描画の占有、隣接色、状態との組合せで判断する。

円や枠の大きさ、SVGの箱、実図案の占有、ラベル、入力領域を区別する。役割別のサイズ群は用途と比較結果から決め、数値を先に正当化しない。小さい補助操作でも実図案と入力先を判別できること、同サイズ群の図案が見かけ上揃うことを確認する。

## 到達性と状態の意味を保つ

文字は収めるために縮めず、配置・改行・領域・適切な内部scrollで必要情報を読めるようにする。マウス、タッチ、キーボードから同じ意味の操作へ到達できる構造を設計する。focus、選択、hover、押下、使用不可、待機、失敗を区別し、色だけに依存しない。キーや戻るの結果は各画面の仕様に従い、一律の取消にしない。

動きは対象と結果の理解を助ける範囲で使い、曖昧な操作・低コントラストを補う手段にしない。動きを減らしても意味と操作は保つ。演出時刻からゲーム状態を再計算しない。

## 実画像と承認範囲を区別する

非UIの見た目は原画像を直接入力し、説明文で代用・補完しない。明示された共通の制作目標と、原画像の見た目を言語化することを区別する。方法は[制作手順](production-and-validation.md#原画像を文章へ置き換えない)を参照する。

参照原画像、制作案、承認済み画像、製品実装は別の証拠である。生成成功、適用一覧、既存のマージ、部品のアクセシビリティ検査は完成画面承認を意味しない。承認は記録された版・画面・状態・寸法に適用し、別画面へ広げない。承認後の変更は差分を特定し、必要な再承認を行う。
