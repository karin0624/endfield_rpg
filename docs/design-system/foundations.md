# UIの基本デザイン

本書は色・文字・余白・形・図案・動きの用途と選び方を扱う。[原則](principles.md)の具体化であり、部品の構造は[共通部品](components.md)、画面への配置は[画面設計](screens-and-patterns.md)に置く。数値・色値の正本は実装ファイルとし、同じ表を複製しない。

## 役割と現在の適用

| 要素 | 役割・判断 | 現在の正本と範囲 |
| --- | --- | --- |
| 色 | 下地、文字、補足、枠、主操作、選択、focus、HP、危険を分ける。図案の意味色と操作優先度を混同しない | [`ui.css`](../../src/web/ui.css)の`--ui-*`。適用先は[一覧](adoption.md)。全画面への適用済みではない |
| 文字 | 本文、操作、主要数値、人物名、画面見出し、補助情報に役割を割り当てる | `ui.css`の書体・`--ui-*-size`、[`party.css`](../../src/web/party.css)の承認範囲、戦闘等は[`style.css`](../../src/web/style.css)と[画面仕様](../../specs/visuals.md) |
| 間隔 | 外周、節、操作間の距離を役割別に揃える。余白で関連・階層・入力分離を示す | `ui.css`の`--ui-inset-*`、`--ui-section-gap`、`--ui-control-gap`。対象画面の配置承認は別 |
| 寸法 | 部品の役割、情報量、入力方法で決める。見える枠と入力領域は区別する | 既存矩形部品は`ui.css`。ホーム・街案の円型サイズ群や試験値は未採用で、製品共通トークンではない |
| 形 | 枠、面、切欠き、円、角、階層と境界の関係を役割で選ぶ。容器の形だけで操作の意味を決めない | 既存矩形の装飾層は`ui.css`。図案型・人物入口等は対象の完成画像と部品で判断 |
| 図案 | 意味を表す図案、場所の絵、実在人物の顔、装飾を分ける。ラベルと組み合わせて識別する | 現在の使用箇所は[部品](components.md)。新図案の色・光学的な占有・サイズ群は対象案で比較し、未決値を公式値にしない |
| 動き | 選択・結果を補助する。静止時にも対象と状態を伝える | `ui.css`のreduced-motion対応、戦闘演出は[戦闘仕様](../../specs/visuals.md)と専用実装 |

### 文字と収まり

用途別の体系は[ADR 0002](../adr/0002-ui-typography.md)を引き継ぐ。共通UIは同梱Noto Serif JPとNoto Sans JPを使い、役割別の太さ・行高を実装で確認する。比較する数値は等幅桁を検討する。remと利用者のroot文字サイズを尊重し、狭幅では構成を変える。承認画像のラスタへ合わせるために文字を横へ潰したり、個別字体補正を増やしたりしない。

文字の読込と実使用、名前・長文・最大桁の収まり、ラベルの改行と入力領域を確認する。特定のデスクトップ画像が承認済みでも、狭幅・低い画面の意匠まで承認済みにはしない。

### 図案の大きさ

図案は、外周の容器、SVG/image箱、clip後の実占有、線幅、内部の負の空間、ラベル、hit領域を別々に確認する。S/M/L等の群を使うなら役割と差の理由を先に示し、同じ群の見かけ上の占有を揃える。例外は画像のclipや機能上の必要性と比較結果を記録する。箱を大きくしただけで図案が大きく読めるとは扱わない。

同じ枠・同じ階層の入口でも、図案内の限定した意味色を使える。色、図案の占有、容器の余白を別の要因として試し、背景と隣接色・線の読める量・状態で評価する。未承認の試験値、見た目だけの推測、認識速度の未測定値を採用根拠にしない。

施設は施設を識別する図案と施設名、人物は本人の原画像と固有名で区別する。その意味の違いだけを理由に共通の枠を変更しない。人物の原画像は保持し、clip・縮尺・表示位置を別に記録する。顔や本人を識別する部分が切れないことを完成画像で確認し、既に見切れている素材を縮めただけで修正済みにしない。

## 読みやすさと入力

通常文字4.5:1、意味の理解に必要な非テキスト部分3:1を設計の基準とする。[W3C文字](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)・[非テキスト](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)に従い、実際に隣接する色と必要な部分を特定する。装飾塗りや使用不可を一律に同じ判定へ入れない。透過面は合成後の下地を確認する。細い線・アンチエイリアスの視認性は実描画でも調べるが、ラスタ値だけを正式な色指定の比率と取り違えない。

[XAG 102](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102)を使う場合は重要な標準サイズの視覚要素4.5:1と大きい要素3:1等、その対象と尺度で別途評価する。円の外径だけで図案を「大きい」と判定せず、W3Cの条件と混ぜない。ratio、axe違反0、VRT、目視のいずれも全要件への適合証明ではない。

focusは入力先、選択は保持される内容、pressedは入力中の反応として分ける。状態で図案・文字・hit領域を意図せず揺らさない。必要な理由は使用不可でも読めるようにし、失敗・待機と区別する。狭幅、低い高さ、長文、各入力方法からの到達性は画面単位で確認する。

カーソルをdefaultにする設計方針は製品全体への適用済みではない。現在の`ui.css`等にはpointerを使う操作がある。方針・現状・今回の変更範囲を区別し、文書更新で実装変更済みとしない。

## 判断を実装値へ接続する

トークンは、採用した用途・状態・尺度を実装へ接続し、一貫して変更できるための手段である。色値や寸法の一覧だけでデザイン方針を代替しない。現行CSS変数の意味から必要な共通化を選び、primitive／semanticやreference／system／component等の層数を固定した新しい管理構造は導入しない。

[デジタル庁の基本デザイン](https://design.digital.go.jp/dads/foundations/)と[ローカルデザインシステム](https://design.digital.go.jp/dads/guidance/local-design-system/)は初期値を導入先の外観規定ではなく編集の起点として扱う。[SmartHRのトークン](https://smarthr.design/products/design-tokens/)と[Fluentのトークン](https://fluent2.microsoft.design/design-tokens)は具体値と意味付けを分ける。本作でも既存のCSS変数と必要な意味から最小構成を選ぶ。[Material 3のトークン](https://m3.material.io/foundations/design-tokens/overview)を含め、外部の層や値をそのまま共通仕様にしない。横断する要件は[アクセシビリティ](accessibility.md)を参照する。
