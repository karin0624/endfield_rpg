# 0012 UI文書の責務と判断・実装値を分ける

日付: 2026-10-11

## 背景

UI指針へ具体値・画面構成・制作ゲート・適用状況が混在し、ADR 0002の「指針を数値の正本」と、CSSを値の正本にする現在の運用が矛盾した。画像提案での修正も、例示された素材だけへ限定したり、未承認寸法を一般規則として扱ったりすると他画面へ適用できない。

## 判断

原則、基本デザイン、部品、画面設計とパターン、制作・検証の責務を分け、アクセシビリティは索引から直接参照できる横断要件にする。ゲーム仕様と進捗は既存のspecsとIssue、適用状況は小さな索引に保持する。必要な責務から文書を選び、ファイル数・トークン層数を先に固定しない。

ADR 0002の用途別文字体系は維持する。数値の正本と重複表を更新する部分を本ADRで置き換え、現在の値はCSS、選び方は[基本デザイン](../design-system/foundations.md)、画面ごとの採用範囲は承認資料へ分ける。ADR 0010の目的からの設計・原画像実入力は維持し、明示された共通制作目標を保持する条件と、仮説・要因別比較・反証から修正する手順を[制作手順](../design-system/production-and-validation.md)へ具体化する。

## 結果

既存実装値、採用済みの画面条件、未承認の試験値を区別できる。共通部品を基本にし、必要な差は役割と比較根拠で判断する。非生成のUI変更と画像生成の双方で根拠と完成画面を確認する。文書改稿は新しい画像・部品・製品実装の採用を意味しない。

構成の参照は[デジタル庁のローカルデザインシステム](https://design.digital.go.jp/dads/guidance/local-design-system/)、[SmartHRのパターン](https://smarthr.design/products/design-patterns/)、[Carbonのパターン](https://www.carbondesignsystem.com/building-blocks/core/patterns/overview)。外部システムの色・寸法・業務アプリの原則を本作へ機械的に移植しない。
