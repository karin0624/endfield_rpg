# 0010: 目的と操作からUIを設計し、原画像を実入力にする

日付: 2026-10-06

## 背景

ホームと街の新案で、背景を変えて仮UIのボタン・配置・人物を踏襲し、静的な場所選択の対象へ会話画面も加えると、必要な判断・操作構造を設計できない。原画像の見た目を文章へ置き換えると、制作担当者と生成モデルが本来の入力を失う。ユーザーは旧v1を不採用とし、UI設計文書の全面的な再整備と、背景・人物の言語化による代用／補完の禁止を指定した。

## 判断

画面の目的、必要情報、操作の結果、遷移・戻る・確定点・時間と所持への影響を、既存のゲーム仕様から設計する。仮UIの外観を新案の制約にしない。対象の完成画像が承認された後はその範囲を守る。

背景・人物の見た目は原画像そのものを渡し、担当者が実見し、生成にも実添付する。入手・実見・生成入力・保存・完成画像承認・製品確認を別々の証拠で扱う。静的ホーム／街と動的ADVは対象を分ける。

[ADR 0002](0002-ui-typography.md)の用途別文字体系、[0003](0003-creative-references.md)の参考作品をゲーム規則の代用にしない判断、[0006](0006-synchronous-presentation-models.md)以降の状態・表示の責務は維持する。リファクタ時に既存外観を保つ判断は、新規UI設計にも同じ外観を強制する意味ではない。

## 結果

設計方法は[画面設計](../ui-screen-design.md)、表現の指針は[デザインガイドライン](../design-guidelines.md)、進行・採否・画像入力は[制作手順](../ui-asset-production.md)へ分ける。ゲーム仕様の正本はspecsのままとし、旧配置表やCSSへの適用記録を承認の代わりにしない。

資料不足や未確定の場所設定で依存する制作を止められる。採否は[制作手順](../ui-asset-production.md#prでの採否)の条件で判定する。本文書の採用は新しい画面・生成物・製品実装の完成を意味しない。
