# 0010: 画面の目的から構造を決め、画像は実入力として扱う

日付: 2026-10-06

## 背景

既存UIの配置や部品を前提にすると、画面に必要な判断・操作から構造を選べなくなる。静的な場所選択と動的な会話では必要な情報と操作が異なる。また、原画像の見た目を文章へ置き換えると、制作や実装で形・配置・素材を直接確認できなくなる。

## 判断

画面の目的、必要情報、操作の結果、遷移・戻る・確定点・時間と所持への影響から設計する。ゲームの振る舞いはspecsに従い、既存UIの外観を新しい構成の自動的な制約にしない。本人が固定したデザインを実装する場合は、その変更範囲と保持条件を守る。

本人がFigmaでデザインし、実装担当は対象版と実画像から再現する。参照画像付きの素材制作・画像編集では原画像を実入力に使う。本人の制作・変更指示と保持条件もその意味を維持して渡す。原画像のない新規制作へ原画像を必須化しない。

## 結果

[画面設計](../ui-screen-design.md)で目的・情報・操作・全パーツの関係を定め、[制作手順](../ui-asset-production.md)で原画像の実利用、素材の確認、Figmaからの実装・比較を扱う。資料不足や未確定の設定がある場合は、依存する対象と工程を特定する。

既存外観を保つリファクタと新しい画面の設計は、変更目的と保持条件から区別する。設計規則の記載、素材の保存、テストの成功を、完成画像の品質・設計との一致・本人判断へ読み替えない。共通規則と画面仕様・制作手順の責務は[ADR 0013](0013-design-document-responsibilities.md)に従う。
