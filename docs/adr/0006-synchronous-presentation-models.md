# 現在状態の同期遷移と直接描画へ分離する

日付: 2026-10-04

## 背景

ゲーム規則、画面判断、focusとdialog、演出進行をDOM closureで所有すると、同じ公開結果の検証にもゲームjourneyと実描画が必要になる。内部属性や呼出順を固定した期待値は、振る舞いを変えないリファクタも妨げた。

ユーザーはブラウザ非依存モデル、薄いNative接続、明示状態の実VRTという3責務への製品改修とE2E廃止を承認した。追加のブラウザ検証は直接作用する実WebGL資源の生成・切替・解放に限定する。

## 判断

ゲームの正本を親applicationへ一つ置き、意味イベントを現在状態へ同期適用する。UI状態は永続ゲームへ混ぜず、draft・画面・focus・dialog・確定recordの表示位置を必要な小モデルで保持する。状態をcommitしてから具体的な外部処理を開始し、同期の再入も現在stateへ適用する。汎用event bus、DSL、EffectRunnerは作らない。

同じ文字列の操作でも次stateで有効なら受理する。時間窓、event.detail、旧action時刻・version、汎用の報酬／取引ID台帳を入力guardへ使わない。[0004](0004-items-equipment-core.md)の状態版・探索／報酬IDによる再送拒否の判断は、この現在状態原則に置き換える。初回街XPと未解決ノードの報酬、未消費の成長権利、所持・残数はゲーム意味として保持する。実資源のownerは遅着完了の所属を表し、入力拒否や保存へ流用しない。

確定結果と表示を分け、各HP・疲労・症状をrecordから投影する。表示時刻と生活半日・戦闘tickを混同せず、既存CSS／素材／画像基準を維持する。直接VRTは任意の正当なstate／phaseから実viewを描く。Nativeはraw深度・rect・接地、HTTP／decode／GPU寿命を扱い、ゲーム判断を持たない。

## 結果

実コアをつないだVitest結合で進行・保存・療養・入力・途中表示を担い、実外観は直接VRT、実GPUは直接資源検証へ分ける。低頻度developer editorの必要時検証は用途に応じて維持する。通常配布と同じ標準minifierで必要な異なる入口をbuildし、その一回の実行へnative V8を付随させる。

方針の採用は最終検証完了や性能達成を意味しない。実行と公開条件は[テスト設計](../testing.md)に従う。
