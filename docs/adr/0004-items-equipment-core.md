# 物品・装備を独立コアから接続する

日付: 2026-10-03

## 背景

[#81](https://github.com/karin0624/endfield_rpg/issues/81)、[#82](https://github.com/karin0624/endfield_rpg/issues/82)、[#83](https://github.com/karin0624/endfield_rpg/issues/83)の方向は合意され、今回のユーザー指示で独立コアの実装が許可された。#83本文には実装を待つ旧記述が残るが、今回指示と#82の最新追記を優先する。重要品は持込み自体から分離、武器・防具は現在ロスト対象外。数値・所有方式・抽選方法は未決。

#79がタイトル・ホーム・main・save・debugを、#84がbattleUi表示演出を並行変更するため、そのファイル群への先行接続を避ける必要がある。

## 判断

ホームストック、持込み／獲得バッグ、永続重要品を単純なデータとして分離する。装備は2枠と能力値投影だけを持ち、所有方式は利用可能IDの入力境界へ残す。状態版と探索／報酬IDで再送を拒否する。数値は引数・定義として注入し、生産用の既定値を置かない。

全アイテムを同じバッグへ入れて例外フラグで保護する案は、重要品の「持込み自体がない」という意味を曖昧にするため採らない。装備効果DSL・売却経済・素材の物語・合成は作らない。抽選方法を先に固定する案も採らず、既存ゲーム乱数を使う方針の注入境界だけを作る。

### 比較用の提案（採用値ではない）

値の正本は`src/content/itemTrials.ts`。既存のロッシはHP20・攻撃8、ギルベルタはHP18・攻撃6なので、固定HP回復8は約4割回復する小さな比較開始点になる。代替はHP回復4（消費頻度高め）／12（1回の価値高め）。疲労を増やす回復スキルとの比較が必要であり、消耗品の供給頻度が未決の段階で優劣は確定しない。

武器の攻撃力+1は既存値の約12〜17%、防具の最大HP+4は約20〜22%の変化。新しい防御計算を増やさず試験できる一方、種類を増やすと単純な最強装備へ収束しやすい。速度補正や防御能力は行動順・ダメージ計算への影響が大きいため初期案に含めない。装備に選択の楽しさを持たせる種類・代償は別途決定する。

価格10・比較用所持金30・店在庫3は「最大3回購入できる」操作検証用の単位。通貨名称や供給・売却相場・初期所持数・本番在庫仕様を採用する提案ではない。回復・装備の効果を先に試し、探索1回あたりの購入可能数で経済を評価する。素材の売値は提案しない。

ロストは保持確率25%／50%／75%を比較候補とする。テスト専用では1個ごとの独立抽選を使うが、これは実装検証用であり採用方法ではない。独立抽選は小さいバッグで全保持／全喪失も起こる。一定個数を必ず保持する方式は結果が安定する一方、端数と少数時のルールが必要になる。「必ず最低1個」「敗北と撤退の差」を勝手に決めず、正式接続までに確定する。

## 結果と接続順

独立コアの利用契約は[物品仕様](../../specs/items.md)へ置く。本編の受入完了や画面で使えることを意味しない。#81/#82/#83を自動クローズしない。

接続には次のファイル境界が必要になるため、各担当と合わせてから変更する。

| 担当境界 | 必要な変更 |
| --- | --- |
| #79 `src/web/main.ts`・ホームUI・初期状態 | 永続ストック・重要品・キャラ別装備を保持。ホームで持込み個数を選び、街とダンジョンの探索開始時に同じ行動IDでバッグを作る。利用可能装備の所有方式を先に確定 |
| `src/game/expedition.ts`・`dungeon.ts` | 必須成長選択のロック、探索/ノード/戦闘IDを照合。アイテム使用結果を名簿・次戦へ反映。既存行動ループを再利用。帰還・敗北処理で物品移送と成長初期化・HP回復・乱数・半日を一括コミット |
| #79 `src/game/save.ts`・`src/web/saveSlot.ts` | 現行形式を更新し、物品と装備等を検証・復元。旧形式の自動削除・移行はしない。探索途中保存を暗黙追加しない |
| #84 `src/web/battleUi.ts`・分岐UI | 使用元・対象・予測回復・取消・使用結果の操作を追加。確定したitem-recoveryイベントだけを表示し、効果・疲労・時計を再計算しない |
| #80 街探索／店 | 合意した1店の品揃え・通貨・価格・在庫を注入。取引単位で時計を進めず、完了時の既存半日へ委譲 |

UI接続前に具体的な経済・回復量・装備効果・ロスト方式を採用する。装備の最大HP変化を現在HPへどう反映するか、成長補正との順序も決める。容量・重量は#88、合成は将来へ分離する。
