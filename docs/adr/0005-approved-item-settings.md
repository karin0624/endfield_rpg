# 承認済み試用設定と物品の本編接続

日付: 2026-10-03

## 背景

独立コアの後、ユーザーが回復品HP8・価格10・初期所持金30、敗北／途中帰還時の1個ごと独立50%保持を承認した。全保持・全損の可能性も確認済み。在庫3は承認外であり、販売上限は導入しない。

続いて武器攻撃力+1・防具最大HP+4、共有所持の実物の排他割当て、装備時はHPを増やさず上限低下時のみクランプすることを承認した。武器2個・防具2個の初期所持はユーザーの採用決定ではなく、実装側が現行2人の試用用に置いた仮初期所持である。最終配布は未決。

## 判断

[先行ADR](0004-items-equipment-core.md)の未採用値・所有方式・抽選方法に関する判断を更新する。現在の値は[物品仕様](../../specs/items.md)と対応する定義ファイルを正本とする。最終バランス・配布・経済とは扱わず、一般素材相場・入手イベント・合成・重要品ストーリーを増やさない。

持込み／獲得の由来は内部記録だけにし、プレイヤーには合計数と単一使用を提示する。消費順は持込み→獲得に統一。アイテムの実回復0は非消費とし、スキルの実回復0時の疲労処理とは分ける。

通常フローがmainへ入った後にホーム・街・探索・保存へ接続する。保存形式は5へ更新して旧形式を拒否し、自動削除しない。装備加算、成長加算、症状倍率の順で一度ずつ投影する。

## 結果

ホームで持込みと装備変更、市場の会話中に買物を行う。取引ごとに半日を消費せず、既存探索完了へ時間と回復を委譲する。帰還は物品移送・乱数・育成初期化・回復を一度に確定する。

#84の演出変更と競合しないよう、戦闘UI接続は別段階で適用する。コアの回復結果は`DungeonActionResult.itemRecovery`として独立して返す。#84完了後、表示側はこの確定結果と既存の敵行動イベントを受領し、効果を再計算しない。現在の接続状況と検証結果はPR #89で追跡する。
