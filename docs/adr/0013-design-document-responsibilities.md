# 0013: 共通デザインと画面仕様・制作手順の責務を分ける

日付: 2026-10-15

## 背景

共通の判断規則へ画面固有値や作業履歴を混ぜると、別画面に誤った条件を適用し、現在の仕様と検証結果を取り違える。原画像の代用説明を避けることと、本人が指定した制作・変更内容を保持することも、独立して扱う必要がある。

## 判断

共通DSは原則・基盤・意味トークン・部品契約・状態・pattern、画面仕様は具体値・素材・配置と割当、制作手順は担当と工程の正本にする。一般DSから用途と制約を参照し、製品固有値を普遍規則へ移さない。本人がFigmaでデザインし、実装担当が固定版を再現する。

参照画像のない新規制作は本人の内容・用途・出力条件から行い、参照画像付き制作・編集は原画像を実入力に使う。本人の制作指示・変更範囲・保持条件を維持し、担当者独自の見た目の文章で原画像を代用しない。視覚品質、設計との一致、ゲーム仕様の操作保証、本人判断を分ける。

[ADR 0010](0010-purpose-first-ui-and-image-input.md)の制作・文書責務の現行判断を本ADRで置き換える。ゲーム規則と表示モデルの責務境界は変更しない。

## 結果

現在の規則は[共通DS](../design-guidelines.md)、[画面設計](../ui-screen-design.md)、[制作手順](../ui-asset-production.md)へ置く。会話・採用経緯・進捗は本文へ累積せず、参照は[文書の責務](../documentation.md)に従って更新する。
