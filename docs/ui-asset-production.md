# UI用画像の制作手順

[UIデザインガイドライン](../specs/design-guidelines.md)に従う。

文字・数値・操作状態・単純な枠・寸法はHTML/CSS/SVGで管理し、AI生成は追加の図案や質感に使う。ボタンを文字ごと生成したり、状態ごとに別の形を作り直したりしない。

生成時は、デザインガイドラインと制作対象に近い既存のUI素材をAIに渡し、両方を参照させる。ガイドラインを配色・状態表現などのルール、既存素材を輪郭・線幅・質感・余白の見本として使う。適切な既存素材がない場合は、[実装CSS](../src/web/style.css)と実画面のスクリーンショットを見本にする。

新規の図案は、参考ゲームの該当画面の参照画像とデザインガイドラインを直接入力し、用途と目指す方向を伝える。PC画面での情報の優先順位・配置・余白・選択状態を先に決め、その構成に必要な図案だけを生成する。

採用済み素材の差分は、元の採用素材と差し替え対象の参照画像を直接入力し、変更する領域・要素だけを指定する。表情差分と同様に無関係な意匠を保持し、指示にない文字や装飾を足さない。

依頼では、作る部品の用途、実際の表示サイズ、背景透過の要否、必要な状態差分、既存素材から変更したい点を指定する。共通のデザインルールはガイドラインを参照し、依頼ごとに書き直さない。

生成後は既存素材と並べ、色・寸法・透過・余白・質感の統一を確認する。色がずれている場合は、該当するトークン色へ補正する。状態差分は同じ原画から作り、輪郭や余白を変えない。実表示サイズで見え方を確認してから採用し、出典・利用条件を[素材メモ](../art-src/README.md)に記録する。

実画面へ適用した後、想定する表示サイズと背景で文字・状態が読み取れ、選択・フォーカス・使用不可を識別できることを確認する。OSで動きを減らした場合も、操作対象を判別できる必要がある。これらの確認だけでWCAGの全要件を満たしたとは判断しない。

## 納品と実画面確認

制作開始時に「画面／用途／必要実寸／透過／状態／既存原画／採用先」を整理する。素材の状態は概念図、原画、採用版、未提供を区別する。編成では背景は新生成、人物は既存原画、枠・数値・状態・ボタンはHTML/CSSである。画像未提供の仲間には名前と「画像なし」を表示し、別人の立ち絵で代用しない。

元データのidentity・version・実寸・hashと、採用版への加工を素材メモへ記録する。無劣化形式変換はデコード後の画素一致も確認する。拡大表示と元画像の高解像度化を区別する。概念図は`docs/ui-concepts/`、原画は`art-src/`、配布素材は`public/assets/`に分ける。

採用版は実際の画面へ接続し、1920×1080で人物・床の比率、文字との衝突、トリミング、画質、通常／選択／非活性／focus／詳細復帰を確認する。背景や人物の取得失敗でも暗い下地・名前・判断情報を残す。狭幅・長文・多数候補・reduced-motionの確認を加え、画面記録とテスト結果はPRへ添える。未確認の素材・適用していない画面は[適用一覧](ui-adoption.md)へ明記する。
