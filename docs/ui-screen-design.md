# 画面の目的・情報・操作を設計する

本書は画面設計の進め方と設計票の正本である。ゲーム規則は[specs/](../specs/overview.md)、表現の指針は[デザインガイドライン](design-guidelines.md)、画像入力・承認・実装・比較の進行は[制作手順](ui-asset-production.md)に置く。本書の設計票は仕様を参照して作り、規則や数値の別の正本にしない。

既存画面は現状調査の対象である。ボタン数・場所・背景・立ち絵の継続を自動制約にしない。各要素を「何を判断・操作するために必要か」で採否判断する。新案の設計中に構成を変えることと、承認後に構成を無断で変えることを混同しない。

情報は0個から考える。既存UIを並べて削るのではなく、各UI・テキストに「この画面に絶対に無くてはいけない理由」があるものだけを置く。重複に加え、プレイヤーの意思決定に影響しない情報量の低い表示も排除する。既存仕様の表示一覧や参考ゲームの項目は採用根拠にならない。別のメニューへ移すだけで必要性の判断を済ませない。

## 画面ごとに決めること

新しい画面案や情報・操作構造を変える対象では、以下を対象Issueや設計資料へ記入する。承認画像への位置合わせ等は既存設計を参照し、今回の差分を特定する。[作業種別ごとの適用条件](ui-asset-production.md#適用条件)に従い、該当しない項目は理由と既存証拠を記す。未決事項は未決とし、承認済み・実装済みを混ぜない。

| 項目 | 記入する内容 |
| --- | --- |
| 対象 | 画面名、入口、対象状態・寸法、今回変える範囲、対象外の画面・機能 |
| 目的 | プレイヤーがここで何を判断し、何を完了するか |
| 必要情報 | 無いと困る具体的な判断と、その判断に必要な最小の情報、参照するゲーム状態／仕様。常設・必要時・別画面を分ける |
| 操作 | 全ての操作対象。ラベル、入力方法、押した直後の結果、選択と実行の区別 |
| 遷移と戻る | 入口・出口・戻り先、元の選択・draft・scroll・focusをどう扱うか |
| 確定点 | draftからゲームへの反映時点、取消の有無、二回目の入力が有効か、完了後の表示 |
| 影響 | 時間・回復・HP・所持／保管／バッグ・装備・フラグ・加入・乱数・保存への変更と非変更 |
| 使用不可・失敗 | disabledと理由、無効入力時の状態保持、上限・待機・I/O失敗、再操作の条件 |
| 未保存 | ゲーム変更、UIのdraft、保存済みデータを区別。破棄確認・取消・保存失敗の結果 |
| 入力と到達性 | マウス・タッチ・キーボード、focus順・復元・dialog中の背面抑止、長文・狭幅・低い画面 |
| 場所と資料 | 場所の設定・用途の決定、未確定点、原画像の役割、参考UI研究の対象。見た目を文章で説明しない |
| 採否と検証 | 各要素の必要性、状態ごとの完成画像、承認範囲、仕様に対応する検証層と未確認事項 |

各操作は次の行形式で具体化する。「押せる」「既存に接続する」だけでは足りない。

| 操作／入力 | 許可条件・押下結果 | 遷移／戻り先 | 確定・取消 | 時間／所持等への影響 | 失敗・focus |
| --- | --- | --- | --- | --- | --- |
| 対象操作 | 現在状態と意味入力 | 画面と保持する状態 | 反映点・再入力の可否 | 変わるもの／変わらないもの、仕様リンク | 拒否理由・保持内容・入力の復帰先 |

仕様上の規則と仮UIの都合を別々に列挙する。たとえば「保存はホームのみ」「街完了で半日」は規則、「ボタンを縦に並べる」「ホームに先頭キャラの立ち絵を置く」「旧4地点を同じ配置で並べる」はそれだけでは新案の要件にならない。仮の加入イベントや試用装備は、決まっていない場所設定・正史・品揃えを決める根拠にしない。

場所・時点の制約と、常設する独立UIの要否を分ける。「ホームで持込み個数を選ぶ」「装備変更はホームだけ」という規則は、ホームに各ボタンや入力欄を常設する要求ではない。操作が必要になる場面から入口を設計し、規則に従ったホームでの出発準備に含める等の配置を検討する。操作へ到達できることと、通常画面に独立したボタンが必要なことを同一視しない。

既存仕様と新要求に矛盾があるなら、その具体的な操作結果を確認する。見た目の変更に便乗してゲーム仕様を変更しない。画面案で不足した操作を製品実装時に即興で足さない。

## 情報と配置を組み立てる順序

1. 画面の目的と、プレイヤーが完了したい行動を決める。
2. その行動に必要な判断を列挙する。
3. 各判断に必要な情報・操作の最小集合を0個から組む。文字なしで成立する構造を先に作り、文字なしでは伝わらない必要情報だけ文字で示す。各要素に、この画面に無いと困る理由を対応付ける。
4. 判断・操作が必要になる適切な場面へ置き、入口・確定点・戻るの流れを組む。ホームに残すか、メニューへ隠すかを出発点にしない。
5. 場所と原画像、参考UIの実画像・動画を確認し、必要な集合に合う意匠と配置を作る。共通部品も役割への適合で採否を決める。
6. 通常だけでなく、使用不可・未保存・確認・失敗・復帰・狭幅等の完成画像で、必要性・読みやすさ・操作結果を検証する。

必要と判定した操作名・制約・結果・読み上げ情報は伝わるように表現する。場所表示も、戻る等の操作で必要な役割が果たせれば追加しない。「枠1/3」「C」「キャラ003」等は、その識別を理解しなくても判断・操作に困らないなら置かない。背景を主役にすることや共通CSSへ統一すること自体を目的にしない。

## ホーム・探索先・街・会話の設計境界

以下は仕様を照合するための対応表であり、新しい配置・装飾の承認ではない。詳細規則はリンク先を読み、設計票に対象の操作を具体化する。

| 対象／目的 | 設計する判断・操作 | 確定・戻る・影響の境界 | 正本と現状確認先 |
| --- | --- | --- | --- |
| ホーム／準備・管理・保存 | 出発・準備・保存を行う場面で、その判断・操作に必要な情報を提示する。対応する操作への到達を設計し、数値・入口・帰還結果の常設を前提にしない | 持込み入力はdraftで、入力だけでは在庫を移さない。編成・装備の確定と保存は別。画面閲覧・準備で時間や療養を進めない | [全体](../specs/overview.md)、[物品](../specs/items.md)、[編成](../specs/party.md)、[保存](../specs/save.md) |
| 探索先選択／行き先を決める | 選べる探索先、選んだ後の行動と準備への入口 | ホームへ戻れる。街画面の閲覧やダンジョン出発準備を開くだけでは時間・所持を消費しない。街に必須成長選択があれば、その既存境界を保つ | [全体](../specs/overview.md)、[成長](../specs/progression.md)、[本編モデル](../src/presentation/campaignModel.ts) |
| 静的な街／場所を選んで活動を始める | 場所を識別して選ぶ、活動結果を確認する、ホームへ戻る。時刻等の現行表示契約と新案の採否を照合し、変更点を設計資料に記録する | 現行は場所の実行で会話活動を開始し、持込みを移す。会話中はホームへ戻れず、無消費取消を新設しない。完了後は街の場所選択へ戻り、選んだ場所を保持する | [街](../specs/adventure.md)、[時間](../specs/time.md)、[物品](../specs/items.md)、[街モデル](../src/presentation/townModel.ts) |
| 動的ADV／本文・分岐を進める | 話者・本文・選択肢と入力対象。表示データに従う人物・場面 | 文章送りと選択は別。選択時のフラグ反映と終了時の完了フラグ・加入を区別し、街完了の半日／回復は終了時に一度確定する | [街・会話](../specs/adventure.md)、[時間](../specs/time.md) |
| 市場の買物／購入する | 品物・効果・価格・個数・所持金・探索バッグ、購入不可理由 | 購入は所持金とバッグを一緒に確定。買物を閉じるだけでは街探索を完了しない。購入ごとの半日は追加しない。装備変更はホームのみ | [物品](../specs/items.md) |
| 保存／再開・破棄確認 | 上書き・未保存破棄の説明、実行／取消、待機・成功／失敗 | 保存確認の取消は現在状態を保持。保存してタイトルへ戻るのは保存成功後。失敗で旧保存を壊さない。未保存破棄の取消は現在状態を保持 | [保存](../specs/save.md) |

本編の入口・戻り先・未保存の現状は[本編モデル](../src/presentation/campaignModel.ts)、表示項目は[本編投影](../src/presentation/campaignProjection.ts)で確認する。既存の表示内容を全て残す指示にはしない。資料ごとに「仕様」「現状の仮表示」「今回の設計決定」を明記する。

### 持込みの規則と現行入力を分ける

持込みの数量・移動・拒否条件は[物品仕様](../specs/items.md)を参照する。設計票では次の境界を照合し、入力欄の位置や探索先選択への移動条件と混同しない。

| 操作段階 | 検証・確定の境界 |
| --- | --- |
| ホームでの準備入力 | draftだけを更新し、在庫・時計を変えない。0は持込みなしとして選択行から除く。保存された所持とdraftを区別する |
| 準備を進める | 空・不正整数・保管超過を拒否し、理由と修正可能な入力を示す。探索先選択後のホーム準備に入力を置く案では、ここで入力を検証し、探索先選択への移動に数量検証を要求しない |
| ダンジョン出発／街活動開始 | 最新の所持と数量を照合し、受理した活動開始と在庫移動を一緒に確定する。準備・街閲覧だけでは移さない。不正入力は部分更新しない |

現行の[本編モデル](../src/presentation/campaignModel.ts)はホームで`carry-changed`を受け、`command.destinations`の`carryValid`で探索先選択への移動を制限する。[本編投影](../src/presentation/campaignProjection.ts)も通常ホームへ数量欄を返す。これは現行UIの接続であり、常設欄・移動制限を新案のゲーム規則にしない。新案の準備入口・検証・戻る・draft保持は対象の設計資料に記録する。

各操作のfocus順と復帰先は本編モデル・[街モデル](../src/presentation/townModel.ts)を照合して設計する。入力部品のキーを画面全体の文章送りへ二重適用せず、会話は[会話仕様](../specs/adventure.md)に従う。編成のEsc確定、会話終了、詳細復帰、保存確認取消を一律の戻るにしない。

### 静的画面と動的画面を混ぜない

静的ホームや街の場所選択の完成案に、話者名・本文パネル・会話選択肢を理由なく追加しない。街で場所を選んだ後の接続先は設計票で示すが、その先のADV意匠は別の対象として扱う。

選択状態を見せるために仮の二段階操作を追加しない。現行の場所押下は活動開始である。プレビューだけの選択、別の実行ボタン、途中取消を提案するなら、それぞれの結果と仕様との差を明示し、未決のまま採用・生成・実装しない。
