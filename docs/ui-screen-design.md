# 画面の目的・情報・操作を設計する

本書は画面設計の進め方と設計票の正本である。ゲーム規則は[specs/](../specs/overview.md)、表現の指針は[デザインガイドライン](design-guidelines.md)、画像入力・承認・実装・比較の進行は[制作手順](ui-asset-production.md)に置く。本書の設計票は仕様を参照して作り、規則や数値の別の正本にしない。

既存画面は現状調査の対象である。ボタン数・場所・背景・立ち絵の継続を自動制約にしない。各要素を「何を判断・操作するために必要か」で採否判断する。新案の設計中に構成を変えることと、承認後に構成を無断で変えることを混同しない。

## 画面ごとに決めること

画像制作前に、以下を対象Issueや設計資料へ記入する。該当しない項目は理由を記す。未決事項は未決とし、承認済み・実装済みを混ぜない。

| 項目 | 記入する内容 |
| --- | --- |
| 対象 | 画面名、入口、対象状態・寸法、今回変える範囲、対象外の画面・機能 |
| 目的 | プレイヤーがここで何を判断し、何を完了するか |
| 必要情報 | 判断ごとの情報、参照するゲーム状態／仕様、表示優先度。常設・必要時・別画面を分ける |
| 操作 | 全ての操作対象。ラベル、入力方法、押した直後の結果、選択と実行の区別 |
| 遷移と戻る | 入口・出口・戻り先、元の選択・draft・scroll・focusをどう扱うか |
| 確定点 | draftからゲームへの反映時点、取消の有無、二回目の入力が有効か、完了後の表示 |
| 影響 | 時間・回復・HP・所持／保管／バッグ・装備・フラグ・加入・乱数・保存への変更と非変更 |
| 使用不可・失敗 | disabledと理由、無効入力時の状態保持、上限・待機・I/O失敗、再操作の条件 |
| 未保存 | ゲーム変更、UIのdraft、保存済みデータを区別。破棄確認・取消・保存失敗の結果 |
| 入力と到達性 | マウス・タッチ・キーボード、focus順・復元・dialog中の背面抑止、長文・狭幅・低い画面 |
| 場所と資料 | 場所の設定・用途の決定、未確定点、原画像の役割、参考UI研究の対象。見た目を文章で説明しない |
| 採否と検証 | 各要素の必要性、状態ごとの完成画像、承認範囲、仕様に対応する検証層と未確認事項 |

各操作は次の行形式で具体化する。「押せる」「既存に接続する」だけでは足りない。

| 操作／入力 | 許可条件・押下結果 | 遷移／戻り先 | 確定・取消 | 時間／所持等への影響 | 失敗・focus |
| --- | --- | --- | --- | --- | --- |
| 対象操作 | 現在状態と意味入力 | 画面と保持する状態 | 反映点・再入力の可否 | 変わるもの／変わらないもの、仕様リンク | 拒否理由・保持内容・入力の復帰先 |

仕様上の規則と仮UIの都合を別々に列挙する。たとえば「保存はホームのみ」「街完了で半日」は規則、「ボタンを縦に並べる」「ホームに先頭キャラの立ち絵を置く」「旧4地点を同じ配置で並べる」はそれだけでは新案の要件にならない。仮の加入イベントや試用装備は、決まっていない場所設定・正史・品揃えを決める根拠にしない。

既存仕様と新要求に矛盾があるなら、その具体的な操作結果を確認する。見た目の変更に便乗してゲーム仕様を変更しない。画面案で不足した操作を製品実装時に即興で足さない。

## 情報と配置を組み立てる順序

1. 入口から目的達成までを、画面・操作・確定点・戻るの流れで組む。
2. 各判断に必要な情報を対応付け、表示の優先度を決める。ラベル・数値・理由を消すと判断できないものは残す。
3. 場所と原画像、参考UIの実画像・動画を確認する。参考の情報構造・操作構造から、本作に必要なものを選ぶ。
4. 情報・操作のまとまりと視線の流れから配置案を作る。共通部品を使うかは役割の適合で決める。
5. 通常だけでなく、使用不可・未保存・確認・失敗・復帰・狭幅等で設計を試す。対象ごとの完成画像へ進む。

「文字を減らす」「背景を主役にする」「共通CSSへ統一する」を目的・判断情報より先に置かない。文字とアイコンのどちらが分かるか、重複表示が別の判断を助けるかを具体的に評価する。常時説明の削減と、操作名・制約・読み上げ情報の欠落は別である。

## ホーム・探索先・街・会話の設計境界

以下は現行仕様と実装への対応表であり、新しい配置・装飾の承認ではない。詳細規則はリンク先を読み、設計票に今回の操作を具体化する。

| 対象／目的 | 必要情報・操作の意味 | 確定・戻る・影響の境界 | 正本と現状確認先 |
| --- | --- | --- | --- |
| ホーム／準備・管理・保存 | 日数・昼夜、所持金・保管数・持込み入力、編成・装備・探索先・保存・タイトルへの入口、帰還結果 | 持込み入力はdraftで、入力だけでは在庫を移さない。編成・装備の確定と保存は別。画面閲覧・準備で時間や療養を進めない | [全体](../specs/overview.md)、[物品](../specs/items.md)、[編成](../specs/party.md)、[保存](../specs/save.md) |
| 探索先選択／行き先を決める | 選べる探索先、選んだ後の行動と準備への入口 | ホームへ戻れる。街画面の閲覧やダンジョン出発準備を開くだけでは時間・所持を消費しない。街に必須成長選択があれば、その既存境界を保つ | [全体](../specs/overview.md)、[成長](../specs/progression.md)、[本編モデル](../src/presentation/campaignModel.ts) |
| 静的な街／場所を選んで活動を始める | 現在地・行き先の識別、利用可能な場所、日数・昼夜、直前の回復／加入等の結果、ホームへの入口 | 現行は場所の実行で会話活動を開始し、持込みを移す。会話中はホームへ戻れず、無消費取消を新設しない。完了後は街の場所選択へ戻り、選んだ場所を保持する | [街](../specs/adventure.md)、[時間](../specs/time.md)、[物品](../specs/items.md)、[街モデル](../src/presentation/townModel.ts) |
| 動的ADV／本文・分岐を進める | 話者・本文・選択肢と入力対象。表示データに従う人物・場面 | 文章送りと選択は別。選択時のフラグ反映と終了時の完了フラグ・加入を区別し、街完了の半日／回復は終了時に一度確定する | [街・会話](../specs/adventure.md)、[時間](../specs/time.md) |
| 市場の買物／購入する | 品物・効果・価格・個数・所持金・探索バッグ、購入不可理由 | 購入は所持金とバッグを一緒に確定。買物を閉じるだけでは街探索を完了しない。購入ごとの半日は追加しない。装備変更はホームのみ | [物品](../specs/items.md) |
| 保存／再開・破棄確認 | 上書き・未保存破棄の説明、実行／取消、待機・成功／失敗 | 保存確認の取消は現在状態を保持。保存してタイトルへ戻るのは保存成功後。失敗で旧保存を壊さない。未保存破棄の取消は現在状態を保持 | [保存](../specs/save.md) |

本編の入口・戻り先・未保存の現状は[本編モデル](../src/presentation/campaignModel.ts)、表示項目は[本編投影](../src/presentation/campaignProjection.ts)で確認する。既存の表示内容を全て残す指示にはしない。資料ごとに「仕様」「現状の仮表示」「今回の設計決定」を明記する。

### ホームと街の操作を照合する例

以下は現行入力の参照例で、ラベル・ボタン形・配置の固定要求ではない。新案は同じ意味の操作を設計票へ対応付け、変更が必要なら仕様との差を確認する。通常ボタンはクリック／タップとfocusしたEnter／Space、数量・装備は入力欄・選択欄から操作する。会話のキーは[会話仕様](../specs/adventure.md)に従い、入力欄・操作部品のキーを画面全体の文章送りへ二重適用しない。

| 操作 | 押下・入力の結果と確定点 | 戻る・使用不可・影響 |
| --- | --- | --- |
| ホームの持込み数量 | UIの持込みdraftを更新する | 0は持込みなし。空・不正整数・保管超過のまま探索先へ進めない。入力だけで在庫・時計を変えず、保存された所持とdraftを混同しない |
| 探索先を選ぶ | 有効な持込み入力なら探索先選択を開く | ホームへ戻れる。画面移動だけで時間・回復・在庫・乱数を変えない |
| 出撃編成を見る | 編集専用の編成を開く | 出発操作を置かない。候補の確定とEscでPTを反映、編成の戻るは編集を保持してホームへ。空PTでも確定は可能、出発可否とは別 |
| 装備を整える | 装備画面を開き、装備変更／解除の受理時にゲームへ反映する | ホームへ戻る。使用中の共有実物等の拒否理由を示す。画面を開くだけでHP・所持・時間を変えず、装備変更の能力／HP影響は[物品仕様](../specs/items.md)に従う |
| 保存 | 上書き確認、実行で保存待ちへ進み、確定bytesをI/Oへ渡す | 取消／Escは現在状態を保持してホームへ。待機中は操作不可、成功／失敗を表示。時間を進めず、保存失敗で旧保存を壊さない |
| 保存してタイトルへ戻る | 上書き確認と保存後、成功時だけタイトルへ | 取消はホーム、失敗もホームと現在状態を保持。保存途中の退出を成功扱いしない |
| タイトルへ戻る | 未保存変更の破棄確認後、実行でタイトルへ | 取消／Escは現在状態を保持。既存保存を上書きしない |
| 探索先で街を選ぶ | 必須成長選択があればそれを先に解決し、街の場所選択へ | 街画面を開くだけでは活動開始・時間消費・持込み移動を行わない |
| ダンジョンを選ぶ／出発する | 選択は出発準備、実出発の受理で入場と持込みを反映 | 出発準備の戻るは探索先へ。出撃者不在・参加不可等は出発disabledと理由。ダンジョン全体の半日は帰還時、ノード移動ごとには計上しない |
| 街で場所を実行する | 選択可能な場所の会話活動を開始し、持込みを移す | 未解放・現在活動中等は拒否して状態保持。開始時に半日を進めない。完了して街へ戻ると選んだ場所のfocusを復元 |
| 街のホームへ戻る | 活動していない街の場所選択からホームへ | 会話途中の無消費取消にしない。街閲覧の終了だけでは半日・回復・購入を追加しない |
| 会話／買物の出口 | 会話の終了で街完了を確定、買物を閉じるだけなら会話へ | 半日・街回復は活動完了時に一度。完了後の必須成長選択を挟んでも再計上しない。購入の所持金／バッグの確定とは別。[会話](../specs/adventure.md)・[物品](../specs/items.md)の契約を保つ |

focus順と復帰先は現状の[本編モデル](../src/presentation/campaignModel.ts)・[街モデル](../src/presentation/townModel.ts)を照合し、新案の設計票に対象操作ごとに記入する。画面見出しへの移動と操作元への復帰を区別し、会話終了・詳細復帰・確認取消を一律の戻るで扱わない。

### 静的画面と動的画面を混ぜない

静的ホームや街の場所選択の完成案に、話者名・本文パネル・会話選択肢を理由なく追加しない。街で場所を選んだ後の接続先は設計票で示すが、その先のADV意匠は別の対象として扱う。

選択状態を見せるために仮の二段階操作を追加しない。現行の場所押下は活動開始である。プレビューだけの選択、別の実行ボタン、途中取消を提案するなら、それぞれの結果と仕様との差を明示し、未決のまま採用・生成・実装しない。

## 今回の失敗案を判定する例

各案は、チェック数や背景の完成度ではなく、どの前提・操作・承認範囲が不足するかで判定する。

| 案 | 判定・止める工程 | 再提出に必要なもの |
| --- | --- | --- |
| 新背景を作り、旧ボタン・旧4地点・旧立ち絵をそのまま置く | 画面設計で棄却。目的・必要情報・全操作結果から採否を説明しておらず、仮UIを制約にしている | ホームと街を別々に設計し、要素と判断・操作の対応、戻る・確定・時間／所持への影響を示す。残す要素も根拠を示す |
| 静的ホーム／街の依頼へギルド会話案を追加する | 対象境界で棄却。接続先の説明を別画面の制作許可へ拡張している | 静的2対象の設計を完成させ、会話制作は別タスクへ分ける |
| 原画像を形容詞・要約・視覚説明へ置換／補完して生成する | 資料確認・生成入力で棄却。原画像が添付されていても見た目の文章による補完は不可 | 原画像の正規取得・担当者の実見・生成への実添付を確認。依頼文はUI仕様・役割・出力条件に限る |
| 武陵城という名称だけから未確定の店・NPC・場所を創作する | 場所設定と資料確認で停止 | ユーザーによる未決設定の確認と公式原画像の入手・実見 |
| 地点のクリックに半日消費、買物ごとにも半日消費を加える | 操作設計で棄却。現行の活動完了の確定点と矛盾する | 街活動開始・購入・完了を分け、既存の時間・在庫規則に対応付ける |
| 背景または通常画像の承認で、focus／disabled・別画面まで実装する | 完成画像承認で棄却。対象状態・画面の承認範囲が不足 | 変更対象の状態・寸法と必要情報を含む完成画像、範囲を特定した承認 |
| 完成画像やCI成功だけを見せて「実装完了」とする | 実装後の検証で棄却 | 本番接続の実画面、同条件pixel比較、仕様に対応する操作・状態の検証を別々に示す |

背景差替えのみが明示された保守作業なら、その限定範囲と既存の承認根拠で判定する。今回のUI再設計にその例外を適用しない。
