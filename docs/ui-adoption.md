# 共通UIの適用一覧

設計値の正本は[デザインガイドライン](../specs/design-guidelines.md)、共通実装は[`ui.css`](../src/web/ui.css)。本書は適用状況を管理する。画面を適用したPRでこの表と実画面証跡を更新する。

| 画面 | 共通部品 | 状況・残る範囲 |
| --- | --- | --- |
| ホームからの編成 | `ui-screen`、`ui-title`、`ui-actions`、`ui-button` | 適用。編集専用で出発なし |
| ダンジョン出発準備 | 同上、`ui-primary` | 適用。実出発だけに主操作を表示 |
| 仲間選択 | 同上、セージ選択と白focus | 適用。候補の内部scroll、人物プレビュー、小さい4枠 |
| キャラ詳細 | `ui-dialog`、`ui-title`、`ui-back` | 適用。表示専用、候補の状態を保持して戻る |
| デバッグ街からの編成 | 編成と同じモジュール | 適用。従来の直接出発コールバック |
| タイトル・ホーム・探索先 | `campaign.css`の既存部品 | 未適用。外周余白・見出し・主副操作を共通部品へ移す対象 |
| 街・会話 | `style.css`の既存部品 | 未適用。背景・会話配置の責務は維持し、操作部品から適用する |
| 装備・ショップ・物品 | `items.css`等の既存部品 | 未適用。UI状態・保存v5の機能は保持 |
| ルート・成長選択 | 既存部品 | 未適用。地図配置と必須選択の仕様を保つ |
| 戦闘・戦闘詳細 | `style.css` / `battleSequence.css` | 新しい画面骨格は未適用。投影札・行動順は全画面アンカーの例外。戦闘演出のCSSは変更しない |

`ui.css`の新しい色・同梱フォント・角落ちの輪郭は`--ui-*`と共通部品に閉じる。旧画面を未検証で一括再配色しない。これは編成専用の永久テーマではなく、次の画面も同じクラスと値を参照する移行単位である。各画面に新しい色セット・似たボタンクラスを複製しない。

## 接続境界

`PartyUiOptions.context`は`edit`と`departure`を区別する。`edit`は出発操作を出さない。`departure`は実入場する`depart`コールバックがある場合に出発を表示する。旧デバッグ呼出しは省略時に出発文脈となる。編成の`edit`と情報取得は同じコアを使う。

`campaignUi.ts`はホーム／探索先の遷移、選んだ持込み数、実入場を所有する。編成モジュールはその数量やセーブを書き換えない。ダンジョンを選んだ時点では持込み・時間を消費せず、出発成功時に既存の`itemSelection()`を渡して持込み指定を消費する。

## 実画面の確認

`tests/e2e/party-ui.spec.ts`は1920×1080でタイトルx64/y48、主操作x1576/y968・280×64、戻るx64/y976・160×48を独立した期待値として検証する。通常と選択で操作位置を変えない。2候補、12/24候補、長名、症状、画像未提供、320/390/900/901/1024/1150/1151px、1920×500、Tab/Space/Enter/Esc、詳細復帰と連打を確認する。マウス保持とSpace押下中の主操作色、白いキーボードfocus、disabledを実画面とcomputed styleで確認し、CIの`campaign-flow-previews`へ保存する。通常版の持込み経路では詳細・候補・出発準備のEscapeと戻るクリックで二重遷移せず、持込み個数・保管数・時刻を保持することを確認する。

実画面の記録は[編成の画面記録](visual-records/formation/README.md)。概念図の生成成功と、実画面の表示・操作成功は別の証拠として扱う。画像の出典と原画・採用版の関係は[素材メモ](../art-src/README.md)を参照する。

実画面の撮影前は表示中の人物画像を`decode()`し、自然寸法が正であること、同梱フォントがloadedであること、タイトルの描画にNoto Serif JPが実際に使われたことを確認する。JSONのreadiness記録とPNGを同じCI artifactへ保存し、画像取得失敗を待機で隠さない。
