# 実装の依存関係

現在の実装契約は[仕様概要](../specs/overview.md)、開発タスクの順序・受入条件・進捗は[ロードマップ](https://github.com/karin0624/endfield_rpg/issues/1)と各Issueを参照する。本書は変更の影響を調べるための依存関係を示す。

| 対象 | 先に確認する契約 | 接続先 |
| --- | --- | --- |
| ゲーム規則・定義 | 対象の公開入力、結果、無効入力と非変更条件 | `src/game/`、`src/content/`と対応するspecs |
| 探索・帰還・生活ループ | 戦闘・会話・成長の確定結果、時間・回復・物品移送 | [探索](../specs/dungeon.md)、[時間](../specs/time.md)、[物品](../specs/items.md) |
| 保存・復元 | 現行状態の整合、保存できる場面、拒否理由 | [保存](../specs/save.md)と確定結果のI/O |
| 画面状態・入力 | 実コアへの意味入力、確定、取消、保持、復帰 | `src/presentation/`と[テスト設計](testing.md) |
| 見た目・素材 | 対象デザイン、全パーツ、状態、原画像と利用条件 | [画面設計](ui-screen-design.md)、[制作手順](ui-asset-production.md)、実viewとrenderer |

ゲーム規則は描画素材の完成を待たずに検証できる。表示や入力の実装はゲームの結果を再計算せず、確定したモデルへ接続する。複数領域にまたがる変更では公開入力から画面とI/Oまでの責務を追い、必要な検証を選ぶ。

タスクの分割や担当順は現在の依存関係から判断する。過去の作業分担を恒久的なファイル所有権にせず、変更前に同時進行の差分を確認する。文書・Issueの更新、素材の保存、個別テストの成功を、機能の接続や全体受入の完了として扱わない。
